# 게재작 구조를 뜯어 검수 기준을 만든다

> **이 문서의 숫자를 그대로 쓰지 마세요.**
> 절차와 규칙은 분야·저널과 무관하게 쓰지만, 숫자와 사례는 **특허·건설 분야
> 논문 한 편(목표 저널 TFSC)에서 실제로 잰 값**입니다. 〔사례〕 표시가 붙은
> 것은 전부 그 논문 이야기입니다. **자기 저널에서 같은 방식으로 다시 재서
> 바꿔 넣으세요.** 무엇을 재는지가 이 문서의 내용이고, 얼마가 나오는지는
> 저널마다 다릅니다.


통독 기록의 글쓰기 관찰(실적 154개)에서 규칙서를 만든다. 이 규칙서가 집필과
검수의 정본이 된다.

---

## 1. 규칙마다 근거 논문 번호를 단다

이게 핵심이다. 근거 없는 규칙은 나중에 이의가 들어오면 방어할 수 없고,
규칙끼리 충돌할 때 우선순위를 정할 수도 없다.

```
|규칙|근거|
|--|--|
|**결론은 짧게.** 발견을 위계 있게 둘셋만. 아홉 개 나열 금지|#30 따라하지말것|
```

`#30`은 통독 기록의 30번 논문이다. 규칙서를 읽다가 의심이 들면 그 논문을
다시 열어 확인할 수 있어야 한다.

## 3. 뽑는 절차

1. 통독 기록에서 **글쓰기 관찰 여섯 칸만 세로로 모은다**(①글 구조만 전편,
   그다음 ②논리 전개만 전편, 이런 식으로)
2. 같은 관찰이 셋 이상에서 나오면 **규칙 후보**로 올린다
3. **"따라 하지 말 것" 칸을 따로 모아 8부(절대 금지 목록)를 만든다.**
   다섯 번 이상 나온 병리는 맨 위로
4. 규칙마다 근거 번호를 달고, **서로 충돌하는 규칙이 있으면 우선순위를 적는다**
5. 이미 확정된 프로젝트 규칙(사용자 지시·전역 규칙)과 충돌하면 **그쪽이 이긴다.**
   충돌 항목을 표로 남긴다

## 3-2. ★구조 해부 (아주 세밀하게)

**게재작의 구조를 뜯어본 뒤, 우리 원고의 구조를 그것과 대조한다.**
이 단계를 건너뛰면 문장만 고치다가 정작 절 구성이 그 저널과 다른 것을 놓친다.

**"몇 절인가"로 끝내지 않는다.** 절마다 도입 문단이 있는지, 마무리 문장이
있는지, 다음 절로 어떻게 넘어가는지, 문단이 몇 개이고 각 문단이 몇 문장인지까지
본다. 우리가 나중에 정해야 할 것이 전부 여기 있기 때문이다.

### 1차: 기계로 초안을 뽑는다

```bash
python scripts/outline_map.py literature/_txt/<파일>.txt
python scripts/outline_map.py --txt literature/_txt --journal <저널> --all
```

목차, 절별 낱말 수와 비중, 문장 수, 문단 수가 표로 나온다. **초안일 뿐이다.**
PDF 텍스트라 절 제목을 놓치거나 문단 경계가 뭉개진다(그 칸은 `?`로 나온다).

### 2차: 원문을 보며 고치고 해부표를 채운다

```bash
python scripts/pdf_render.py "<게재작>.pdf" 1 6 2.0
```

렌더링해서 **눈으로 보며** 초안을 고치고, 아래 항목을 채운다.

### 해부 항목 (A) 문서 전체

| 항목 | 무엇을 적나 |
|--|--|
| 분량 | 총 쪽수, 총 낱말 수 |
| 절 | 최상위 절 개수, 하위절 총 개수, **깊이 몇 층까지** |
| 비중 | 절별 쪽·낱말 비중(%) |
| 번호 | 번호 체계(1 / 1.1 / 1.1.1), **번호 없는 절이 있는가** |
| 그림·표 | 각각 몇 개, **첫 그림이 몇 쪽에 나오는가**, 몇 쪽마다 하나꼴인가 |
| 수식 | 몇 개, 본문인가 부록인가 |
| 각주 | 몇 개, 어느 절에 몰리는가, 무엇에 쓰는가 |
| 참고문헌 | 개수, 자기 저널 비율 |
| 부록 | 개수, 이름 방식, 무엇을 싣는가 |

### 해부 항목 (B) 절마다 공통으로 보는 것

**모든 절에 대해 같은 칸을 채운다.** 하나라도 비면 그 자리는 나중에 우리
취향으로 정하게 된다.

| 항목 | 무엇을 적나 |
|--|--|
| 제목 | 낱말 수, 형식(명사구/동명사/의문형), 관사 유무, `and` 유무 |
| 분량 | 쪽·낱말·문단 수 |
| 문단 길이 | 문단당 문장 수의 **최소·중앙값·최대** |
| **도입** | 절 서두에 예고 문단이 있는가. 있으면 몇 문장, 어떤 형식 |
| **마무리** | 절 끝에 요약·다음 예고 문장이 있는가, 없는가 |
| 첫 문장 | 유형(주장/현상/전환/인용) |
| 마지막 문장 | 유형(경계/해석/예고) |
| **전환** | 다음 절 첫 문장이 앞 절을 **지시사로 받는가**, 이음말인가, 없는가 |
| 인용 | 그 절의 인용 개수, 어디에 몰리는가 |
| 수치 | 그 절의 수치 개수 |
| 하위절 | 개수, 하위절당 문단 수, **한 문단짜리가 있는가** |

### 해부 항목 (C) 절별 전용

**서론**

- 여섯 걸음(현상 / 왜 중요한가 / 누가 쓰나 / 선행연구 / 갭 / 기여)이 각각
  **몇 문단, 몇 문장**이고 **순서**가 어떤가
- 첫 문장 유형, 첫 문단의 인용 개수
- **갭이 몇 개**인가, 갭 문단이 몇 번째인가, 갭 형식(반쪽씩 / 번호 나열 / 차원 누락)
- **연구 질문**: 어디에 놓는가(몇 번째 문단), 번호를 다는가, 몇 개, 각 몇 낱말
- **기여**: 몇 개, 어디에 놓는가, 기여마다 인용을 다는가
- **구성 예고 문단**: 있는가, 몇 문장, 형식("Section 2 develops …")

**이론·문헌 검토**

- 소절 개수와 **나누는 축**(주제별 / 방법별 / 시간순 / 갈래별)
- 각 소절의 형식(전통 → 한계 / 갈래 나열 / 논쟁 소개)
- **소절이 나열인가 연쇄인가**(다음 소절 첫 문장이 앞 소절 결론을 받는가)
- 마지막 소절이 우리 공백으로 이어지는가

**자료·방법**

- **자료와 방법이 한 절인가** 나뉘는가
- **단계 번호를 쓰는가**("Stage 1. …"), 몇 단계인가, 이름 형식
- 순서가 자료 → 전처리 → 지표 → 모형 → 검증인가
- 선택마다 이유를 붙이는가, 그 문장 형식
- 수식 위치, 기호 풀이 방식
- 재현 안내(자료·코드)를 어디에 두는가
- 그 절의 표·그림 개수

**결과**

- **첫 하위절이 검증인가**
- 하위절 순서가 **연구 질문 순서와 같은가**
- 표를 먼저 제시하고 해석하는가, 해석 뒤에 표를 두는가
- 강건성이 본문인가 부록인가
- 절 끝에 **경계 문장**이 있는가

**논의**

- 첫 문단이 결과 압축인가
- 이론적 함의 / 실무 함의 / 한계의 **순서와 문단 수**
- **한계가 논의에 있는가 결론에 있는가**

**결론**

- 문단 수
- **연구 질문을 되받는가**, 방법 단계를 되짚는가
- 한계·후속연구의 위치와 분량
- 마지막 문장 유형

**앞뒤 장치**

- 초록: 문장별 기능 순서(배경 → 공백 → 본 연구 → 수치 → 의의)
- 하이라이트 유무·개수, 키워드 개수
- 감사말·서약·저자 기여의 위치

### 3차: 나란히 놓고 우리 원고와 대조한다

1. 위 표를 논문별로 채운 뒤 **같은 항목끼리 가로로 놓는다**
2. **공통인 것은 따른다.** 갈리는 것만 우리가 정한다
3. 절 제목은 **실제로 쓰인 것 중에서 고른다**(창작 금지).
   실측 예: "Data collection" 42편, "Data and method" 18편, "Scope" 2편
4. **우리 원고의 절 구성을 그 옆에 놓는다.** 절 개수, 순서, 이름, 분량 비중,
   하위절 깊이를 항목별로 맞춰 본다
5. **어긋난 자리마다 선택지를 만들어 드린다.** "게재작 몇 편 중 몇 편이
   이렇게 한다", 득실, 우리 상황을 붙인다(`SKILL.md` §0-B의 형식).
   **고치는 것은 저자가 정한다**
6. **다수파와 다르게 가기로 했으면 그 이유를 기록에 남긴다.** 예: "논의를
   결론과 합치는 것이 다수파지만 질문을 되받을 자리가 필요해 독립 절로 둔다"
6. 분량 대역을 정한다(절별 비중과 전체 쪽수)

틀은 `templates/구조지도.md`에 있다.

### 이 지도는 계속 쓴다

- **집필 전**: 각 절을 쓰기 전에 대응하는 게재작 절을 다시 읽는다
- **집필 중**: 도입·마무리·전환을 그 절의 형식대로 쓴다
- **검수**: `15_직접대조_검수.md`의 소절·장 층 대조가 이 지도를 쓴다
- **탈고 후**: 구성 예고와 실제 절이 맞는지 대조한다
- **목차가 바뀌면 이 파일도 같이 고친다**

## 4. 총칙에 넣을 것

규칙서 맨 앞에 셋을 적는다.

- **주장은 몇 개인가.** 모든 문단은 그중 하나에 복무한다
- **관찰 수위 항목**은 규정된 수위를 넘지 않는다(금지선 목록)
- 이 규칙서는 **"어떻게 쓰나"만 다룬다.** "무엇을 쓰나"는 별도 문서가 정본

## 5. 규칙이 흩어지면 체계화한다

지적을 하나 받을 때마다 규칙을 하나 붙이다 보면 규칙이 세 문서에 흩어진다.
그때는 **의심 차원 목록**으로 묶는다. 차원마다 뿌리가 된 실제 사고, 검사 방법,
담당 회차를 붙인다. 실제로 쓴 12차원은 `07_검수회전.md` §4에 있다.

## 6. 규칙서를 쓸 때의 함정

- **규칙을 많이 만들려고 하지 않는다.** 지키지 않는 규칙은 없는 것만 못하다
- **"게재작이 그렇게 한다"가 아니라 "게재작 몇 편 중 몇 편이 그렇게 한다"로
  적는다.** 반반이면 그건 규칙이 아니라 선택지다
- 실제 사례: 긴 직접 인용 뒤 쪽수를 다는 경우 11건, 안 다는 경우 15건이었다.
  저쪽이 반반이므로 **"저널 때문이 아니라 우리 원고 안의 어긋남 때문에"**
  고친다고 적었다
