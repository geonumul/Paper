# 그림과 표: 양식을 통째로 베낀다

> **이 문서의 숫자를 그대로 쓰지 마세요.**
> 절차와 규칙은 분야·저널과 무관하게 쓰지만, 숫자와 사례는 **특허·건설 분야
> 논문 한 편(목표 저널 TFSC)에서 실제로 잰 값**입니다. 〔사례〕 표시가 붙은
> 것은 전부 그 논문 이야기입니다. **자기 저널에서 같은 방식으로 다시 재서
> 바꿔 넣으세요.** 무엇을 재는지가 이 문서의 내용이고, 얼마가 나오는지는
> 저널마다 다릅니다.


**데이터와 수치는 우리 것, 양식은 전부 게재작 것이다.** 선 두께·색·폰트·크기·
격자·테두리·범례 위치·캡션 문구·표 규칙선·주석 말투까지 하나하나 재서 맞춘다.

글이 아무리 좋아도 그림에서 티가 난다. 실제로 "클로드 티가 너무 많이 난다"는
지적을 그림에서 받았다.

---

## §1. 세 겹으로 잰다

| 겹 | 무엇 | 도구 |
|--|--|--|
| ① **수치 추출** | 폰트 이름·크기·색, 선 두께·색·점선 패턴, 채움 색, 도형 종류 | `figure_forensics.py` |
| ② **이미지 판독** | 배치·정렬·여백·격자 유무·마커 모양·범례 자리·전체 인상 | `pdf_render.py`로 PNG를 만들어 **직접 본다** |
| ③ **나란히 대조** | 우리 그림을 같은 배율로 렌더링해 그들 것과 **붙여 놓고** 본다 | 둘 다 |

**셋 중 하나만 하면 반드시 놓친다.**

- 수치만 보면: 폰트 이름이 subset 코드(`AdvOT863180fb`, `ABCDEF+Times`)로 나와
  **세리프인지 산세리프인지 이름으로는 알 수 없다.** 배치·정렬·여백도 안 잡힌다
- 이미지만 보면: 선 두께가 0.72pt인지 1.0pt인지, 회색이 `#d9d9d9`인지
  `#cccccc`인지 눈으로 못 맞춘다
- 우리 것을 나란히 안 놓으면: 각각은 그럴듯한데 붙여 놓으면 다른 경우가 있다

### 〔사례〕 실제로 돌린 예

```bash
# 1. 어느 쪽에 그림·표가 있나
python scripts/figure_forensics.py "게재작.pdf" --scan

# 2. 그 쪽의 양식을 수치로
python scripts/figure_forensics.py "게재작.pdf" 6

# 3. 같은 쪽을 이미지로 (그리고 직접 읽는다)
python scripts/pdf_render.py "게재작.pdf" 6 6 2.0
```

수치 쪽이 준 것:

```
- 크기 분포: 6.5pt 650자          - 글자 색: #000000 650자
- 선 두께: 0.72pt 24개, 2.15pt 24개, 0.75pt 6개
- 선 색: #d9d9d9 30개, #bf504c 12개, #7f64a1 12개, #000000 5개
- 점선: [] 0 (실선) 550개, [4.3017 4.3017] 0 (점선) 12개
- 세리프 판정: 불가 (subset 코드)
```

이미지 쪽이 준 것: 표는 가로 규칙선 세 줄뿐이고 **세로선이 없다**. 캡션이 표
위에 있고 "Table 3"이 굵게 한 줄, 설명문이 그 아래 줄. 빈 칸은 대시가 아니라
**공백으로 비워** 둔다. 그림은 여섯 패널이 각각 검정 테두리 상자 안에 있고,
가로 격자만 옅게 있으며, 연도 라벨이 기울어져 있고, 범례가 각 패널 아래에 있다.

**두 결과가 서로를 확인해 준다.** 빨간 실선(`#bf504c`, 2.15pt), 보라 점선
(`#7f64a1`, 대시 4.3), 옅은 회색 격자(`#d9d9d9`, 0.72pt)가 이미지에서 본 것과
정확히 맞는다.

### 저널마다 다르다

위 예는 어떤 저널의 논문이고, **산세리프 6.5pt에 컬러**를 쓴다. 반면 다른
저널의 게재작 4편은 **세리프체·흑백·각진 모서리**였다. **여러 저널을 섞어
평균 내지 않는다. 목표 저널의 최근 게재작만 잰다.**

## §2. 그림 사양서

게재작에서 이 항목을 **전부** 채운다. 하나라도 "모르겠다"로 남으면 그 항목은
우리 취향으로 정하게 되고, 거기서 티가 난다. 틀은
`templates/그림표_사양서.md`에 있다.

### 판면과 크기

- 단폭인가 양단 통짜인가 (본문 단 폭에 맞췄는가)
- 가로세로 비율, 그림 하나가 차지하는 쪽 비중
- 해상도(래스터라면), 벡터로 실었는가

### 테두리와 격자

- **축 테두리를 사방 다 치는가**, 아래·왼쪽만 치는가 (matplotlib 기본은
  위·오른쪽이 없다. 사방을 치는 저널이면 `spines`를 전부 켜야 한다)
- 테두리 두께(pt)와 색
- **격자선이 있는가**. 있으면 가로만인가 둘 다인가, 색과 두께, 실선인가 점선인가
- 패널이 여러 개면 패널을 상자로 감싸는가, 패널 사이 간격

### 축

- 눈금 방향(안쪽/바깥쪽), 길이, 굵기
- 눈금 라벨 각도(0도인가 기울였는가), 폰트 크기
- 축 이름을 쓰는가 안 쓰는가, 쓰면 어떤 표현인가(`Share of fusions (%)`)
- 축 범위를 어디까지 잡는가(0에서 시작하는가), 눈금 간격
- 이중 축을 쓰는가, 쓰면 좌우 라벨을 어떻게 구분하는가
- 천단위 콤마, 백분율 기호 표기

### 선·마커·색

- **선 두께를 pt로**(예: 본선 2.15pt, 격자 0.72pt)
- **색을 hex로.** 몇 가지 색을 쓰는가(2색인가 흑백인가)
- 점선을 쓰면 **대시 패턴 수치까지**(`[4.3017 4.3017]`)
- 마커 모양(원·사각·삼각), 크기, **속을 채우는가 비우는가**
- 계열이 여럿이면 색으로 구분하는가 마커로 구분하는가 둘 다인가

### 범례와 라벨

- 범례 위치(그림 안/아래/오른쪽), 테두리와 배경이 있는가
- 범례 항목 이름의 표현(약어인가 풀어 쓰는가)
- **끝점에 직접 라벨을 다는가, 범례를 쓰는가**
- 값 라벨(막대 위 숫자 등)을 다는가

### 흐름도·모형도라면

- **모서리가 각진가 둥근가** (둥근 모서리는 논문 그림에서 드물다)
- 상자 테두리 두께·색, 채움이 있는가
- 화살표 두께, 머리 모양, 실선인가 점선인가
- 전체를 바깥 상자로 한 번 더 감싸는가
- 단계 번호를 상자 안에 쓰는가

### 캡션과 노트

- 캡션이 그림 **아래**인가 위인가
- `Fig. 1.`인가 `Figure 1.`인가, 번호 뒤가 마침표인가 콜론인가
- 캡션이 명사구인가 문장인가, 마침표로 끝나는가
- 캡션 폰트와 크기, 굵기
- 노트를 다는가. 달면 위치·크기·문구 형식(`Note: …`)

## §3. 표 사양서

표는 그림보다 더 자주 티가 난다. 항목이 많고 우리 습관이 그대로 드러난다.

### 규칙선

- **가로 규칙선 몇 줄인가**(booktabs 방식은 맨 위·머리 아래·맨 아래 셋)
- **세로선을 쓰는가** (학술지 표는 대개 안 쓴다)
- 규칙선 두께(맨 위·아래가 더 굵은가)
- 부분 규칙선(`cmidrule`)을 쓰는가

### 캡션

- 표 **위**인가 아래인가
- `Table 3`이 한 줄, 설명문이 다음 줄인가, 한 줄에 이어 쓰는가
- 번호가 굵은가, 설명문이 굵은가
- 마침표로 끝나는가

### 본문

- 글자 크기(본문보다 몇 pt 작은가. 실측 6.5pt 같은 값)
- 정렬: 문자는 왼쪽, 숫자는 오른쪽인가 소수점 기준인가
- **소수 자리 수**를 몇 자리로 통일했는가
- 천단위 콤마를 쓰는가
- **빈 칸을 어떻게 두는가**: 공백인가 대시인가 `n.a.`인가
- 행 번호 열을 두는가
- 단위를 열 제목에 두는가 각 칸에 두는가
- 유의수준 별표 표기(`*`, `**`, `***`)와 그 기준을 어디에 적는가
- 표준오차를 괄호에 넣는가 별도 열로 두는가
- 굵게·이탤릭을 쓰는 자리(합계 행, 채택된 설정)

### 주석

- 주석 위치(표 바로 아래), 글자 크기
- **길이**(실측 중앙값 76자·14낱말 수준). 본문을 대신하지 않는다
- 문구 형식(`Note: Two-sided t-test.` / `Note: Bold indicates …`)
- 출처 줄(`Source:`)을 다는가 (게재작의 7%만 단다면 우리도 안 단다)

## §4. 말투와 용어까지 베낀다

**그림·표 안의 글자도 원고다.** 낱말 규칙이 똑같이 적용된다.

- **축 이름·열 제목의 어법**을 게재작에서 가져온다. 우리가 지어낸 압축어를
  쓰지 않는다
- 캡션 문장 형식을 뽑아 본다
  ```bash
  python scripts/find_usage.py --journal <저널> "^Fig(\.|ure) [0-9]"
  python scripts/find_usage.py --journal <저널> "^Table [0-9]"
  python scripts/find_usage.py --journal <저널> "Note[:.] "
  ```
- 범례 항목 이름을 본문 용어와 **글자까지 일치**시킨다. 실제로 그림은
  "Construction/Other", 표는 "Construction itself/Residual"로 어긋나 있었다
- 약어를 그림 안에서 처음 쓰지 않는다. 캡션에서 풀어 준다

## §5. 우리 그림을 만들고 나서

### 5-1. 나란히 놓고 본다

```bash
# 그들 것
python scripts/pdf_render.py "게재작.pdf" 6 6 2.0 out/
# 우리 것 (그림 스크립트가 PNG를 만든다면 그대로, PDF면 렌더링)
python scripts/pdf_render.py "figures/fig2.pdf" 1 1 2.0 out/
```

두 PNG를 **직접 보고** 다른 점을 목록으로 적는다. 목록이 빌 때까지 고친다.
이것도 수렴 루프다(`15_직접대조_검수.md` §7과 같은 방식).

### 5-2. 정렬 점검 일곱 항목

1. 상자의 좌우 정렬
2. 상자의 위아래 라인업
3. 상자 안에 상자가 있으면 내부 좌우 간격이 똑같이 남는지
4. 화살표가 틀어진 것이 없는지
5. 화살표 간격이 일정한지
6. 글씨의 중앙 정렬과 좌우 정렬
7. 간격이 너무 넓거나 좁은 곳이 없는지

### 5-3. 재사용할 matplotlib 뼈대

**아래 값은 예시다. 반드시 §2에서 잰 값으로 바꾼다.**

```python
import matplotlib
matplotlib.use("Agg")
import matplotlib.pyplot as plt

INK = "#000000"
BLUE, ORANGE = "#1f4e8c", "#c8631a"      # 계열 색은 실측값으로

plt.rcParams["font.family"] = "serif"
plt.rcParams["font.serif"] = ["Times New Roman"]   # 시스템에 있는지 확인
plt.rcParams["text.color"] = INK
plt.rcParams["axes.edgecolor"] = INK
plt.rcParams["axes.labelcolor"] = INK
plt.rcParams["xtick.color"] = INK
plt.rcParams["ytick.color"] = INK
plt.rcParams["mathtext.fontset"] = "stix"

fig, ax = plt.subplots(figsize=(6.6, 4.3), dpi=300)
fig.patch.set_facecolor("white")
ax.set_facecolor("white")
for spine in ax.spines.values():        # 기본은 위·오른쪽이 없다
    spine.set_visible(True)
    spine.set_color(INK)
    spine.set_linewidth(1.0)            # 실측 두께로
ax.grid(False)                          # 격자를 쓰는 저널이면 색·두께까지 맞춘다
```

흐름도는 `FancyBboxPatch`(둥근 모서리)가 아니라 `Rectangle`(각진 모서리)로
그린다. 폰트는 시스템에 실제로 있는지 확인하고 쓴다.

## §6. 데이터는 건드리지 않는다

양식을 고칠 때 **수치·계열·모수는 그대로 둔다.** 실제 사례에서도 스타일만
전면 교체하고 데이터는 산출 파일 원본 그대로 두었다. 스타일 수정과 수치 수정을
같은 회차에서 하지 않는다.

## §7. 그림이 판면을 어떻게 먹는지 본다

- **축 이름을 글씨로 쓰면 그림 상자가 가운데여도 축이 치우쳐 보인다.**
  게재작이 어떻게 하는지 보고, 못 재면 **우리 그림들끼리 일관되게** 맞춘다.
  실제로 왼쪽 라벨이 먹는 폭을 42%에서 35%로 줄여 맞췄다
- **그림 하나가 쪽수를 늘리지 않게.** 한 줄이 삐져나와 한 쪽이 늘어난 적이
  있다. 그럴 때는 셋 중 하나를 아주 살짝 줄인다
- 그림·표가 한 쪽을 통째로 차지하지 않게 부동체 배치를 조정한다
  (`10_제출_Elsevier.md` §4)
- **표만으로 채운 쪽을 만들지 않는다.** 표를 나누더라도 문단별 설명이 함께 있어야 한다
- 표가 판면을 넘지 않게, 오른쪽에 빈 공간이 많으면 게재작 처리 방식을 본다

## §8. 그림 안의 글자도 검수 대상이다

- **그림 안에 절 번호를 그려 넣으면 본문 번호를 바꿀 때 따라오지 않는다.**
  실제로 그림 4·5가 존재하지 않는 절(3.6)을 가리키고 있었다. 열 회차를 돌고도
  그림 안의 글자를 안 봐서 놓칠 뻔했다
- 그림 노트의 모수를 본문과 대조한다. 그림 2가 N = 4,200이라 했으나 연도별
  수치의 모수는 3,240이었다
- 계열 이름이 표와 다르면 안 된다
- 그림이 표를 못 따라온 경우도 있다. 표 3은 다섯 계열인데 그림 2는 두 계열만
  그리고 있었다

## §8-2. 표·그림 안의 글자도 전수로 검수한다

**본문만 검수하면 표와 그림 안은 통째로 빠진다.** 전수 대장을 만드는 도구들이
표 줄(`|`로 시작)과 캡션을 본문에서 제외하기 때문이다. 그래서 따로 돌린다.

```bash
python scripts/word_census.py 원고.md --floats --journal <저널>
```

표 안, 캡션, 주석(`Note:`)의 낱말만 뽑아 코퍼스와 대조한다. 〔사례〕 이렇게
돌렸더니 표·캡션·주석에서 낱말 345개가 나왔고, 그중 **36개가 목표 저널
코퍼스에 아예 없었다.** 본문 검수만 했으면 그대로 남았을 것이다.

### 표에서 보는 것

| 볼 것 | 무엇을 |
|--|--|
| **용어** | 열 제목·행 이름이 본문 용어와 **글자까지 같은가**. 코퍼스에 있는 말인가 |
| **문법** | 열 제목의 형식이 통일되었는가(명사구인지 문장인지), 단수·복수 |
| **글 흐름** | 열 순서가 본문 서술 순서와 같은가. 행 정렬이 뜻을 만드는가 |
| **주석 길이** | 게재작 대역 안인가〔사례: 중앙값 76자·14낱말〕 |
| **주석 용어** | 본문에서 정의한 말만 쓰는가. 주석에서 처음 나오는 약어가 없는가 |
| **주석 문장** | 완결된 문장인가 구인가. 게재작 형식과 같은가(`Note: Two-sided t-test.`) |
| **주석 중복** | 본문과 글자 그대로 겹치지 않는가 |
| **자립성** | 본문 없이 표만 봐도 무엇을 재고 무엇이 대비되는지 아는가 |

### 그림에서 보는 것

| 볼 것 | 무엇을 |
|--|--|
| **그림 안 용어** | 축 이름·범례·상자 안 글자가 본문 용어와 같은가 |
| **그림 안 문법** | 축 이름의 형식(대문자·단위 표기)이 통일되었는가 |
| **그림 안 흐름** | 흐름도의 단계 순서가 본문 서술 순서와 같은가 |
| **캡션** | 그림만 보고 무엇인지 아는가. 형식이 게재작과 같은가 |
| **주석** | 길이·용어·문장 형식. 모수(N)와 기간이 본문과 맞는가 |
| **절 번호** | 그림 안에 절 번호를 적었으면 실제 절과 맞는가 |
| **자립성** | 본문 없이 그림과 캡션만으로 이해되는가 |

### 순서

1. `--floats`로 **낱말을 전수로** 뽑아 대조표를 만든다(표·캡션·주석)
2. 그림 안 글자는 **이미지로 열어 눈으로 읽는다**(`pdf_render.py`). 텍스트로
   안 뽑히는 자리가 많다
3. 표 하나, 그림 하나마다 **자립성 물음 하나**를 던진다: 본문을 가리고 이것만
   봤을 때 무엇을 말하는지 아는가
4. 주석은 **길이를 세고** 게재작 대역과 견준다
5. 걸린 것은 대조 대장의 별도 칸에 적는다

**표와 그림 안의 글자도 원고다.** 열 회차를 돌고도 그림 안의 절 번호 오류를
놓칠 뻔한 적이 있다.

## §9. 표의 셈을 직접 검산한다

- 표 2: 군집별 N 합계가 모수와 맞는지, 비중이 N/모수와 맞는지
- 표 3: 열 합계가 100인지, 행마다 후기 빼기 전기가 표기와 맞는지
- 표 4: 분해 둘의 합이 관측 변화와 같은지
- 표 6: 가중평균이 합계행을 재현하는지
- 표 9와 부록 표 A.1: 사건 수가 같은지

## §10. 표와 그림은 홀로 읽혀야 한다

심사자가 본문에서 몇 쪽 떨어진 표를 마주칠 수 있다. **표가 실제로 몇 쪽에
떨어지는지 재고**, 표마다 "읽는 이가 반드시 알아야 하는 것"을 정해 캡션·열
이름·주석 안에서 찾는다. 실제로 43항목을 그렇게 점검했다.

## §10-2. 파일 규격 (출판사 요구)

양식을 아무리 맞춰도 **파일 규격이 안 맞으면 제작 단계에서 되돌아온다.**
투고 안내문의 그림(artwork) 항목을 직접 읽고 표로 만든다.

| 항목 | 안내문 규정 | 우리 |
|--|--|--|
| 파일 형식 | 벡터(PDF·EPS) / 래스터(TIFF·PNG·JPEG) 중 무엇을 받는가 | |
| 최소 해상도 | 선그림·사진·혼합이 각각 몇 dpi인가 | |
| 색 | 컬러를 받는가, 인쇄는 흑백인가, 색 공간(RGB/CMYK) | |
| 크기 | 단폭·양단의 실제 mm 또는 pt | |
| 글자 크기 | 그림 안 글자의 최소 크기 | |
| 선 굵기 | 최소 선 굵기(가는 선은 인쇄에서 사라진다) | |
| 파일 이름 | 번호와 맞추는 규칙 | |
| 하나에 여러 패널 | (a)(b) 표기 방식 | |

**직접 확인하는 방법**

- 벡터로 내면 해상도 문제는 없다. **가능하면 PDF로 낸다**
- 축소했을 때 글자가 읽히는지 본다. **인쇄 크기로 출력하거나 그 크기로
  렌더링해서** 확인한다
- **흑백으로 바꿔 보고** 계열이 구분되는지 본다. 색으로만 구분하면 흑백 인쇄에서
  뭉개진다. 마커 모양이나 실선·점선으로도 구분되게 한다
- 가는 회색 선(격자 등)이 인쇄에서 남는지 확인한다

## §10-3. 크기와 배치에서 실제로 난 사고 〔사례〕

**① 자동 잘라내기가 글자 크기를 흔든다**

저장할 때 잉크에 맞춰 여백을 잘라내면(`savefig(..., bbox_inches="tight")`)
**그림마다 파일 폭이 달라진다.** 그 상태로 본문 폭에 맞추면 LaTeX이 각각 다른
배율로 늘린다. 같은 8pt로 그렸는데 인쇄면에서 한 그림은 9.9pt(1.16배), 다른
그림은 7.4pt(0.97배)가 되었다.

- **목표 폭을 정하고 그 폭으로 저장한다.** 예: 단폭 그림은 `figsize`의 가로를
  본문 단 폭에 맞추고 잘라내기를 쓰지 않는다
- 잘라내기를 꼭 써야 하면 **저장 뒤 파일의 실제 폭을 재서** 서로 같은지 본다
- **인쇄면에서 글자 크기를 재서** 그림들끼리 같은지 확인한다

**② 분자와 분모의 단위가 달랐다**

표가 헐렁한데 글자는 줄바꿈되는 모순된 증상이 있었다. 원인은 **폭 예산은 한 단
폭(12.05cm)으로 잡고 분모만 페이지 폭(17.11cm)으로 쓴 것**이었다.

> **"휑한데 글자는 줄바꿈된다"처럼 모순된 증상은 단위가 섞였다는 신호다.**
> 폭을 계산할 때 단폭인지 양단인지 먼저 정하고, 분자와 분모를 같은 단위로 쓴다.

**③ 배치를 먼저 하고 선을 나중에 그렸다 (같은 실수 3회)**

흐름도 하나에서 세 번 났다. 줄기가 상자 중심이 아닌 곳에서 나가고, 나가는
높이가 4pt 어긋나고, 가로선과 세로 줄기가 7pt 떠서 아예 안 닿았다.

- **배치는 제약이 먼저, 공간이 나중.** 모든 상자는 **자기 연결선이 나가는
  높이**에 놓는다. 남는 자리에 놓고 선을 나중에 그리면 어긋난다
- **그림 스크립트가 스스로 검산을 찍게 한다.** 예를 들어 이렇게 출력한다

  ```
  이음매 검산: 전처리 중심 80.0 · 두 갈래 51.0과 109.0 · 그 중간 80.0
  ```

  숫자가 안 맞으면 그림을 열어 보기 전에 알 수 있다

**④ 같은 자리가 두 번 재발하면 식을 본다**

글자가 도형에 걸려 높이를 두 번 올렸는데 두 번 다 같은 자리에서 또 걸렸다.
뚜껑 깊이가 `높이 × 0.13`이라 **높이를 올리면 뚜껑도 같이 깊어져** 글 넣을
자리는 늘 같은 비율이었다.

> **같은 증상이 두 번 재발하면 값이 아니라 값을 정하는 식을 본다.**

## §11. 파일 이름과 재현

- **파일명, `\label`, 인쇄되는 번호가 모두 같아야 한다**
- PDF와 PNG를 함께 낸다. 시스템이 하나만 받으면 PDF를 쓴다
- **재현 스크립트를 실제로 돌려 대조한다.** 임시 폴더로 출력해 글자·도형 수·
  크기를 비교한다. 실제로 세 번 어긋나 있었다
- **국문판과 영문판 그림 스크립트를 따로 두면 반드시 어긋난다.** 어느 것이
  정본인지 파일 첫 줄에 적는다
- 국문 대역에서는 표만 본문에 넣고 그림은 `[그림 1. 제목]` 위치 표시만 남긴다

## §12. 체크리스트

```
[측정]
□ 목표 저널 게재작에서 그림·표가 있는 쪽을 --scan으로 찾았다
□ figure_forensics로 폰트·크기·색·선 두께·점선 패턴·채움을 수치로 뽑았다
□ 같은 쪽을 렌더링해 이미지로 직접 봤다
□ 사양서의 모든 항목을 채웠다 ("모르겠다"가 없다)
□ 재지 못한 항목은 "재지 못했다"고 적고 다른 기준을 세웠다
□ 여러 저널을 섞지 않았다

[제작]
□ 실측값(두께 pt, hex 색, 대시 패턴, 폰트 크기)을 그대로 스크립트에 넣었다
□ 축 테두리·격자·눈금 방향을 실측대로 맞췄다
□ 마커 모양·채움·크기를 맞췄다
□ 범례 위치·테두리·항목 이름을 맞췄다
□ 캡션 형식(위치·번호 표기·마침표·굵기)을 맞췄다
□ 표 규칙선·정렬·빈 칸 처리·소수 자리·주석 문구를 맞췄다
□ 그림·표 안의 용어가 본문과 글자까지 같다

[대조]
□ 우리 것과 그들 것을 같은 배율로 렌더링해 나란히 봤다
□ 다른 점 목록이 빌 때까지 고쳤다
□ 정렬 일곱 항목을 점검했다
□ 데이터·수치는 하나도 안 바뀌었다
□ 그림 안의 절 번호·모수·계열 이름이 본문과 맞는다
□ 표의 셈을 검산했다
□ 파일명 = label = 인쇄 번호, 재현 스크립트가 같은 그림을 만든다
```
