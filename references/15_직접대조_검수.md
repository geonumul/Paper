# 직접 대조 검수: 낱말부터 전체까지, 게재작을 근거로

> **이 문서의 숫자를 그대로 쓰지 마세요.**
> 절차와 규칙은 분야·저널과 무관하게 쓰지만, 숫자와 사례는 **특허·건설 분야
> 논문 한 편(목표 저널 TFSC)에서 실제로 잰 값**입니다. 〔사례〕 표시가 붙은
> 것은 전부 그 논문 이야기입니다. **자기 저널에서 같은 방식으로 다시 재서
> 바꿔 넣으세요.** 무엇을 재는지가 이 문서의 내용이고, 얼마가 나오는지는
> 저널마다 다릅니다.


**이 문서가 검수의 본체다.** `07_검수회전.md`는 순서와 회전 관리이고, 여기는
**한 단위씩 게재작과 직접 대조하는 방법**이다.

---

## §0. 무엇을 하는 것인가

원고의 모든 단위(낱말·문장·문단·소절·장·전체)에 대해 이 물음에 답할 수 있어야
한다.

> **"이건 어떤 근거로 이렇게 썼어?"**
> → "게재작 X의 [어느 자리]가 [이렇게] 하고 있고, 우리 자리도 같은 기능이라
> 그 방식을 따랐다."

답할 수 없으면 그 자리는 아직 검수가 안 된 것이다.

**세 가지를 못 박는다.**

1. **기계는 판정하지 않는다.** 검사기는 후보를 줄이는 용도로 먼저 한 번 돌릴
   뿐이고, **판정의 근거는 언제나 게재작의 실제 문장을 읽은 결과**다.
   "검사기가 통과시켰다"는 근거가 아니다
2. **밖에서 말을 가져오지 않는다.** 고칠 말은 게재작에 실제로 쓰인 말 중에서,
   그리고 가능하면 **우리 원고 안에 이미 있는 말** 중에서 고른다
3. **선례를 못 찾으면 지어내지 않는다.** "선례를 찾지 못했다"고 기록하고,
   우리 논리만 두거나 저자 판단으로 넘긴다

## §1. 준비: 대조군과 대장

### 1-1. 대조군 게재작을 고른다

전체 코퍼스와 대조하면 시간이 무한히 든다. **자리별 대조군**을 미리 정한다.

| 대조군 | 몇 편 | 무엇에 쓰나 |
|--|--|--|
| **A급**(기준 논문) | 2-4편 | 문단 논리·절 구성·서술 방식의 1순위 근거. 우리와 방법·자료가 가장 가까운 것 |
| **B급**(같은 저널 같은 갈래) | 10-20편 | 문형·용어·수치 서술의 대역 |
| **C급**(그 저널 전반) | 나머지 전부 | 낱말이 그 저널에 존재하는지 확인용 |

A급은 **처음부터 끝까지 다시 읽어 절 구성을 통째로 옮겨 적어 둔다.**
그래야 "우리 4.2절에 해당하는 자리"를 지목할 수 있다.

### 1-2. 게재작 구조 지도를 꺼낸다

**집필 전에 이미 만들어 두었어야 한다**(`03_규칙서_뽑기.md` §3-2,
`templates/구조지도.md`). 여기서는 그것을 꺼내 쓰고, 통독 뒤에 새로 알게 된
것을 보탠다. 없으면 지금이라도 만들고 시작한다.

한 줄 요약표는 이런 모양이다.

```markdown
| 논문 | 절 구성 | 결과 절의 문단 배열 | 한계 형식 | 특징 |
|--|--|--|--|--|
| #6 Zhao 2026 | 6절 | 검증 → 표 제시 → 해석 → 경계 | First/Second/Finally 3개 | 부록에 예측 결과 전부 |
```

### 1-3. 근거 대장을 연다

`templates/대조검수_대장.md`를 복사해서 쓴다. **대조한 것은 전부 여기에
남는다.** 남기지 않으면 다음 회차에 같은 자리를 또 판정하게 되고, 판정이
회차마다 달라진다.

## §2. 모든 층위에 공통인 여섯 걸음

```
① 읽는다 (기계 결과를 보지 않고, 사람이 읽듯이)
② 걸린 자리를 적는다 (개수를 정해 놓고 채우지 않는다)
③ 게재작에서 같은 기능의 자리를 찾는다 (§8의 검색 조리법)
④ 항목별로 대조한다 (무엇이 같고 무엇이 다른가)
⑤ 판정한다: 유지 / 대체 / 유보(저자 결정)
⑥ 대장에 기록한다 (근거 논문·자리·이유. 유지도 기록한다)
```

**⑤에서 "대체"를 고르면 반드시 ⑥ 다음에 재독(§7)으로 돌아간다.** 고친 문장은
새 문장이므로 아직 검수되지 않았다.

## §3. 낱말 층 (전수)

### 낱말 층은 이렇게 돈다 (한 턴에 한 몫)

```bash
python scripts/word_census.py 원고.md --txt <코퍼스> --min-freq 1 --out outputs/낱말_대장.md
python scripts/word_judge.py outputs/낱말_대장.md 1 60 --md 원고.md --txt <코퍼스>
python scripts/word_judge.py outputs/낱말_대장.md 1 60 --md 원고.md --txt <코퍼스> --apply
python scripts/word_judge.py outputs/낱말_대장.md 1 60 --md 원고.md --txt <코퍼스> --verify
```

`word_judge`는 **근거로 갈리는 것만** 적는다. 수식·참고문헌·캡션에만 있는 것, 게재작 8% 이상이 쓰는 것, 그 꼴만 없고 어간이 흔한 것, 조사표 항목 코드 옆에서 원자료를 가리키는 것이다. 근거마다 **어느 논문 어느 문장인지** 함께 적는다.

### 근거는 기계가 되짚을 수 있게 적는다

사람이 읽기 좋게 다듬으면 검증이 막힌다. 실제로 그렇게 아홉 건이 "근거가 틀렸다"로 잘못 걸렸다.

| 이렇게 적으면 안 된다 | 왜 | 이렇게 적는다 |
|--|--|--|
| `[Fatima2025]` | 코퍼스 파일 이름이 아니라 못 찾는다 | `[Fatima2025_SpatialScale_OccupationalInjury]` |
| `[키] "문장…"` | 따옴표가 대조 앞머리에 끼어든다 | `[키] 문장…` |
| `[키]는 문장…` | 조사가 대조 앞머리에 끼어든다 | `[키] 문장…` |
| 굽은 부호를 곧은 것으로 바꿔 적기 | 원문과 글자가 달라진다 | **원문 그대로 옮긴다** |

**기계가 되짚을 수 없는 근거는 근거가 아니다.** 다시 확인할 수 없는 문장은 주장일 뿐이다.

**`--apply` 다음에는 반드시 `--verify`를 돌린다.** 대장의 근거는 기계가 쓴 것이라, 아무도 되짚지 않으면 그대로 굳는다. 되짚기는 근거가 이름 댄 논문에 그 낱말이 실제로 있는지, 인용한 문장이 그 논문에 있는지, "참고문헌에만 있다"고 적힌 낱말이 정말 본문에 없는지를 본다.

**되짚을 것이 없어 지나간 행은 통과가 아니다.** 근거가 "게재작 34편이 쓴다"로 끝나면 되짚기가 맞춰 볼 문장이 없다. 그 말은 그렇게 적힌 글자를 서른네 편이 담고 있다는 뜻일 뿐이고, 그 낱말이 우리와 같은 일을 한다는 말이 아니다. 한 원고에서 그런 행이 **143개** 있었고 그중에 원고에서 마흔여섯 번 쓰는 낱말이 있었다. 되짚기가 이제 그런 행을 따로 세어 내놓는다. **숫자가 0으로 깨끗한데 원고가 그대로인 상태를 만들지 않기 위한 것이다.**

**도구를 고쳤으면 옛 판이 적은 행을 다시 적는다.**

```bash
python scripts/word_judge.py outputs/낱말_대장.md 1 1769 --md 원고.md --txt <코퍼스> --apply --refresh
```

적기는 판정 칸이 빈 행만 채우므로, 같은 구간에 다시 돌려도 이미 적힌 행은 그대로 남는다. `--refresh`는 **근거가 부실한 행만** 다시 적는다. 인용이 없거나, 적힌 인용이 그 논문에 되짚어지지 않는 행이다. ★가 붙은 행과, 코퍼스에 문장이 있을 수 없는 갈래(참고문헌에만 나오는 말, 고유명, 조사표 항목)는 건드리지 않는다. **사람이 손으로 적어 둔 판정을 기계가 덮지 않게 하는 것이 요점이다.**

**그리고 되짚기는 사실만 본다. 뜻은 못 본다.** 논문 이름이 맞고 문장이 그 논문에 있어도, 그 문장이 우리 문장과 **같은 뜻·같은 문법 자리**로 그 낱말을 쓰는지는 사람이 읽어야 안다. 그래서 되짚기가 매 몫마다 세 행을 지목한다. **그 세 행은 눈으로 읽고 넘어간다.**

**낱말이 통과해도 이음이 다를 수 있다.** 낱말 층을 닫기 전에 이음을 한 번 견준다.

```bash
python scripts/collocation.py 원고.md --txt <코퍼스> --top 30
```

〔사례〕 `read`는 게재작 10편이 써서 낱말로는 통과했다. 그러나 게재작의 read는 *문서를 읽는다*이고 우리 것은 *결과를 해석한다*였다. `read as`와 `read against`가 게재작 **0편**인데 우리는 여덟 번 썼고, 같은 자리에 게재작이 쓰는 `understood as`(7편), `in light of`(11편)를 우리는 한 번도 안 썼다. **한 원고에서 여덟 번, 게재작 쉰한 편에서 0번인 구문은 어휘가 아니라 말버릇이다.**

지목은 **원고에서 많이 쓰는 낱말부터** 한다. 서른세 번 쓰는 낱말은 주장을 떠받치고 한 번 쓰는 낱말은 안 그렇다. 〔사례〕 한 몫에서 `housekeeping`(33회)이 지목됐고, 게재작 7편이 전부 선행연구지표 문헌에서 같은 뜻으로 쓰는 것이 확인됐다. 그 낱말의 뜻이 어긋났다면 그 위에 선 발견이 통째로 어긋났을 것이다.

〔사례〕 자동 60행·잔여 0·지적 0으로 닫힌 배치를 되짚었더니 **다섯 행이 틀렸다.** `outlier`, `bands`, `man-day` 같은 본문 낱말이 "수식 안의 LaTeX 명령"으로 적혀 있었다. 되짚지 않았으면 그대로 닫혔을 것이다.

**남은 것이 그 턴에 사람이 읽을 몫이다.** 대개 한 몫에 스무 줄에서 서른 줄이 남는다. 자동화의 목적은 대신 답하는 것이 아니라 **읽을 만큼 줄이는 것**이다. 남은 줄에 한 줄짜리 이유를 붙여 넣으면 그 순간 전수 판정이 아니라 전수 서명이 된다.

`★ 다른 꼴`로 나온 것은 지적이 아니라 **후보**다. 게재작이 같은 말의 다른 꼴을 쓴다는 사실만 적고, 바꿀지는 저자가 정한다.〔사례〕 `overfit`은 게재작에 0편인데 `overfitting`은 4편 10회였다.

### ★이 층의 규칙 하나

**원고에 나오는 모든 낱말을 하나씩 판정한다.** "몇 개를 확인했다", "주요 용어를
살펴봤다", "표본으로 몇 개 보니 괜찮다"는 **이 층을 안 한 것이다.**

- 판정 대상은 **행 개수가 정해진 표**다. 표의 모든 행에 판정이 붙기 전에는
  낱말 층을 닫지 않는다
- 보고는 언제나 **"전체 N개 중 M개 판정, 남은 것 K개"** 형식으로 한다.
  개수 없이 "확인했다"고 말하지 않는다
- 판정 대상에서 빼는 것은 **미리 정한 목록뿐이다**(아래). 읽다가 "이건 괜찮겠지"
  하고 건너뛰지 않는다

### 1. 대조표를 만든다 (전수)

```bash
python scripts/word_census.py 원고.md --txt literature/_txt --journal <저널>        --out outputs/낱말_대조표.md
python scripts/word_census.py 원고.md --ngram 2 --out outputs/낱말_결합형.md
```

원고의 내용어를 전부 뽑아 코퍼스 편수·비율과 함께 표로 만든다. 비율이 낮은 것,
즉 **위험한 것부터** 나온다. 실제 규모의 예: 영문 원고 하나에서 대조 대상
**2,186개**, 그중 코퍼스에 아예 없는 것 **263개**, 8% 미만 **618개**.

**`--abbr`도 반드시 돌린다.** 약어는 낱말 대조표에서 빠진다(대문자 두 글자는
낱말로 안 잡힌다). 대화에서 굳어진 줄임말이 원고에 남아 있는지 여기서 본다.

```bash
python scripts/word_census.py 원고.md --abbr --journal <저널>
```

**`--ngram 2`도 반드시 돌린다.** 낱말을 조합해 만든 말은 각 낱말이 흔해도
결합형이 코퍼스에 없다. 지어낸 말은 대개 여기서 잡힌다.

### 2. 판정 대상에서 빼는 것 (미리 정하고 기록한다)

| 빼는 것 | 왜 |
|--|--|
| 기능어(the, of, and 등) | 판정할 것이 없다 |
| **코드·매개변수 이름**(`random_state`, `UMAP`, `CPC`) | 번역·교체하지 않는다 |
| 고유명사(기관·회사·지명) | 코퍼스 빈도로 판정할 대상이 아니다 |
| 숫자·단위 | |

**이 목록에 없는 것은 전부 판정한다.** 목록을 늘리려면 그 이유를 대장에 적는다.

### 3. 한 줄씩 판정한다

각 행에 대해 순서대로 본다.

1. **코퍼스에 있는가**(표의 비율). 0%면 그 자리는 위험하다
2. 굴절형이라 형태만 없는 것인지 본다(표에 어간 비율이 붙어 나온다)
3. 8% 미만이면 **걷어내거나 풀어 쓴다**
4. 8% 이상이어도 **끝이 아니다. 쓰인 문장을 읽는다**
   ```bash
   python scripts/find_usage.py --journal <저널> --per-file 3 "<낱말>"
   ```
   **맥락 다섯**을 본다(`01_게재작수집_실측.md` §6).
   **①뜻 ②가리키는 대상 ③문법 자리와 연어 ④강도·수위 ⑤정의를 붙이는가.**
   하나라도 어긋나면 빈도가 높아도 근거가 아니다
5. 바꿔야 하면 **원고 안에서 대체어를 먼저 찾는다.** 실제로 초록의 한 표현이
   걸렸을 때 이미 원고 여섯 군데에서 같은 개념을 다른 낱말로 부르고 있었다
6. 판정을 **유지 / 대체 / 유보** 중 하나로 적고 근거를 남긴다
7. 바꾼 뒤 **그 낱말이 쓰인 모든 자리를 다시 본다.** 한 곳만 고치면 표기가 갈라진다

### 4. 읽으면서 걸린 것도 따로 적는다

기계 표와 별개로, **원고를 처음부터 끝까지 읽으며 멈춘 자리**를 적는다.
빈도가 높아도 우리 문장에서 어색한 낱말은 표에서 안 걸린다. 둘은 서로를
대신하지 못한다.

### 5. 진행 기록

대장(`templates/대조검수_대장.md`)에 이렇게 남긴다.

```
낱말 층: 전체 2,186행 / 판정 완료 2,186 / 남음 0
  - 코퍼스에 없음 263개 → 대체 41, 유지 209(고유명사·표준 표기), 유보 13
  - 8% 미만 618개 → 대체 22, 유지 596
  - 읽다가 걸린 것 17개 → 대체 9, 유지 8
  판정 안 한 행: 0   ← 이 숫자가 0이 아니면 층을 닫지 않는다
```

### 판정하며 함께 지킬 것 셋

1. **하나를 찾으면 같은 종류를 전수 검사한다.** 습관어 하나가 나왔다면 그
   종류가 더 있다. 한 건으로 끝내지 않는다
2. **바꾸기 전에 우리 원고 안의 다른 자리를 먼저 센다.** 외부 기준만 보고
   내부 일관성을 안 보면 **과잉 수정**이 난다. 실제로 두 번 고쳤다가 두 번 다
   되돌렸다
3. **유지 판정도 기록한다.** 안 적으면 다음 회차가 같은 것을 다시 잰다

### 판정할 때 조심할 것

- **빈도가 높아도 맥락이 다르면 근거가 아니다**
- **낱말을 바꾸면 문장이 흔들린다.** 반드시 문장 층으로 내려가 다시 읽는다
- 한 문단에 같은 동사가 두 번 생기지 않았는지, 약어 정의가 사라지지 않았는지 본다

## §4. 문장 층 (전수)

### ★이 층의 규칙 하나

**원고의 모든 문장을 한 문장씩 판정한다.** "주요 문장을 봤다", "몇 군데
고쳤다"는 이 층을 안 한 것이다.

```bash
python scripts/unit_census.py 원고.md                      # 개수부터 센다
python scripts/unit_census.py 원고.md --sents --out outputs/문장_대장.md
```

문장마다 번호가 붙는다(`4.2-P3-S2` = 4.2절 세 번째 문단의 두 번째 문장).
**대장의 모든 행에 판정이 붙기 전에는 문장 층을 닫지 않는다.**
실제 규모의 예: 영문 원고 하나에서 절 33개, 문단 203개, **문장 779개**.

보고는 **"779개 중 M개 판정, 남음 K개"**로 한다.

문장 하나마다 다음을 확인한다. **문장의 기능을 먼저 정하고, 그 기능의 문장을
게재작에서 찾아 나란히 놓는다.**

### 4-1. 문장의 기능을 정한다

| 기능 | 예 |
|--|--|
| 현상 제시 | "Patenting in X has grown over the last ten years" |
| 선행 관행 규정 | "While prior studies often treat X as …" |
| 갭 진술 | "Harder to find is a comparison that …" |
| 선택 정당화 | "We used X, as it is considered …" |
| 절차 서술 | "We constructed a network in which …" |
| 표·그림 지시 | "Table 3 reports …" |
| 결과 보고 | "The results indicate that …" |
| 해석 | "This result is consistent with …" |
| 경계 | "These figures do not, however, tell us …" |
| 한계 | "One limitation of this study is that …" |

### 4-2. 같은 기능의 게재작 문장을 뽑는다

```bash
python scripts/find_usage.py --journal <저널> --before 1 --after 1 "Table [0-9] (shows|reports|presents)"
python scripts/find_usage.py --journal <저널> "One limitation|limitation of (this|our) study"
python scripts/find_usage.py --journal <저널> "we (constructed|computed|scored|assembled)"
```

**앞뒤 문장을 함께 본다**(`--before 1 --after 1`). 그 문장 하나가 아니라
**그 문장이 앞뒤와 어떻게 이어지는지**가 우리가 배울 것이다.

### 4-3. 항목별로 대조한다

| 항목 | 무엇을 보나 |
|--|--|
| **낱말** | 이 문장에 쓴 낱말이 §3을 통과했는가. 바꾼 낱말 때문에 뜻이 흔들리지 않았는가 |
| **문법** | 시제 3층, 능동·수동, that/which, 지시대명사 명시, 비교 대상 명시 (`05_영작규칙.md`) |
| **논리** | 이 문장의 주장 강도가 근거 크기와 맞는가. 인과어를 쓰지 않았는가 |
| **흐름** | 앞 문장의 끝과 이 문장의 시작이 이어지는가. 소리 내 읽어 확인 |
| **기능** | 이 문장이 문단의 메시지에 실제로 복무하는가. 없어도 되는 문장인가 |
| **근거** | 같은 기능의 게재작 문장과 형태가 어긋나지 않는가 |

### 4-4. 판정

- **유지**: 근거 문장을 대장에 적는다. "우리 3.4절 첫 문장은 #6의 3.2절
  도입 문장과 같은 형태(선택 + as it is considered)"
- **대체**: 게재작 문형을 그대로 쓰되 **문장 골격은 우리 것으로 다시 세운다**
  (5단어 연쇄가 겹치면 유사도 검사에 걸린다)
- **유보**: 선례를 못 찾았다. 대장에 "선례 없음"으로 적고 저자 판단으로

### 4-5. 자주 나온 병

- 낱말을 바꾸다 **한 문단에 같은 동사가 두 번**, 한 문장에 같은 말이 겹쳤다
- 약어를 빼니 **다른 곳의 정의가 사라졌다**
- 대명사를 고치니 **선행사가 없어졌다**
- 문장을 매끄럽게 다듬다 **원래 있던 조건절이 빠져 주장이 넓어졌다**

마지막 것이 가장 위험하다. **다듬기가 주장을 키우면 그것은 다듬기가 아니다.**

## §5. 문단 층 (전수)

### ★이 층의 규칙 하나

**모든 문단에 카드를 하나씩 만든다.** 문단 카드가 없는 문단은 검수되지 않은
문단이다.

```bash
python scripts/unit_census.py 원고.md --paras --out outputs/문단_대장.md
```

대장에 문단마다 한 행이 생긴다(`4.2-P3`). 각 행의 **메시지 한 줄·빌드업·근거
게재작·판정**이 채워져야 그 문단이 끝난다. 203개면 203행이다.

**긴 문단만 보거나 결과 절만 보지 않는다.** 서론의 짧은 전환 문단, 절 도입
문단, 표를 설명하는 문단도 전부 대상이다.

### 5-1. 문단 카드를 채운다

문단마다 하나씩. 이 카드가 "이 문단은 어떤 논리로 했어?"에 대한 답이다.

```markdown
### [4.2절 세 번째 문단]

**메시지 한 줄**: 정보·제어 계열의 상승을 이끈 것은 신규 진입자가 아니라
기존 공급자다.

**빌드업**: 추세 수치 → 귀속 분해 → 선행연구 대비 → 실명 확인 → 경계

**문장별 역할**:
1. (결론) 두괄식 주장
2. (근거) 분해 결과 수치
3. (비교) 선행연구 수치와 대조
4. (확인) 실명 사례
5. (경계) 이것만으로 말할 수 없는 것

**근거 게재작**: #6 Zhao(2026) 4.3절 두 번째 문단. 그쪽도 "수치 → 분해 →
문헌 대비 → 경계" 순서이고, 경계 문장을 문단 끝에 둔다. 우리 자리도 결과
문단이라 같은 배열을 따랐다.

**앞 문단과의 연결**: 앞 문단이 "무엇이 변했나"를 끝냈고, 이 문단 첫 문장이
"누가 그것을 이끌었나"로 받는다. 지시사로 직접 받음.

**판정**: 유지
```

### 5-2. 확인 항목

| 물음 | 못 지켰으면 |
|--|--|
| 메시지가 **하나**인가 | 문단을 쪼갠다. 한 줄로 안 써지면 메시지가 둘이다 |
| 첫 문장이 그 메시지인가 | 두괄식으로 고친다(전환 문단은 다리 문장 허용) |
| 문장들이 그 메시지를 향해 **빌드업**하는가 | 복무하지 않는 문장을 뺀다 |
| 문장 사이가 논리로 이어지는가 | 순서를 바꾸거나 연결을 명시한다 |
| 앞 문단 끝과 이 문단 첫 문장이 손을 잡는가 | 이음말이나 지시사로 잇는다 |
| 문법·시제가 문단 안에서 일관되는가 | 시제 3층으로 맞춘다 |
| **게재작의 같은 자리도 이렇게 하는가** | 그들 배열로 바꾼다 |

### 5-3. 메시지 사슬

문단 카드의 **메시지 한 줄만 모아 서론부터 결론까지 이어 읽는다.**

```
1장-①  현상: 특허는 늘었는데 내는 것은 건설기업이 아니다
1장-②  왜 중요한가: ...
...
6장-③  결론: ...
```

이어 읽어서 **말이 되면** 논문이 한 줄기다. 중간에 끊기거나 같은 말이 두 번
나오면 그 자리가 문제다. 실제로 이 방법으로 다음을 잡았다.

- 앞에서 안 나온 개념이 갑자기 튀어나오는 자리
- 뒤에서 할 말을 앞에서 미리 해 버린 자리
- 같은 메시지를 두 문단이 나눠 갖고 있는 자리

## §6. 소절·장·전체 층 (전수)

같은 방식으로 단위만 키운다. **한 번에 한 층위만** 들고 처음부터 끝까지 간다.

**소절과 장도 개수를 세고 전부 판정한다.** `unit_census.py`가 절 목록과 절별
문단·문장 수를 준다. 소절이 33개면 33행을 채운다. "주요 절만" 보지 않는다.

### 소절 층

| 확인 | 게재작 대조 |
|--|--|
| 소절이 하려는 말이 **한 줄로 써지는가** | 그들의 같은 소절도 한 줄로 써지는가 |
| 문단 배열이 논리적인가(나열인가 연쇄인가) | 그들의 배열 순서와 비교 |
| 문단 수와 길이가 대역 안인가 | 그들의 소절당 문단 수 |
| 소절 제목이 내용과 맞는가 | 그들의 절 제목 실용례(창작하지 않는다) |

**한 줄로 안 써지면 하려는 말이 둘이다.** 제목에 미리 예고하거나 전환문을 둔다.

### 장 층

| 확인 | 게재작 대조 |
|--|--|
| 장이 하려는 말이 명확한가 | |
| **장 서두의 예고와 실제 소절이 일치하는가** | 그들도 예고를 두는가, 어디에 두는가 |
| 소절이 나열인가 **연쇄**인가 | A급의 같은 장이 어느 쪽인가 |
| 장 경계 전환이 매끄러운가 | 앞 장 마지막 문단과 다음 장 첫 문단을 붙여 놓고 본다 |
| 장 길이 비중이 대역 안인가 | 그들의 장별 쪽수 비중 |

**장 층에서만 보이는 것이 있다.** 소절 층에서는 경계만 보기 때문에 놓친다.
실제로 2장을 한 호흡에 읽고서야 소절 셋이 단순 나열이 아니라 연쇄 연역임을
알았다.

### 전체 층

- 처음부터 끝까지 **한 번에 통독한다.** 부분을 오가며 읽지 않는다
- **후렴**(반복되는 한 문장)이 초록·서론·방법·결과·논의에 있는가
- 구성 예고와 실제 절이 맞는가
- 표·본문·초록의 수치가 삼중으로 맞는가
- 용어가 처음부터 끝까지 한 뜻인가, 정의보다 먼저 쓰인 곳이 없는가
- **같은 것을 두 이름으로 부르지 않는가.** 긴 이름과 줄인 이름이 섞여 있으면, 줄인 것을 처음 쓸 때 밝히고 그 뒤로는 한 이름으로 간다
  〔사례〕 조절변수를 `external institutional intervention` 12회와 `external intervention` 9회로 부르며 같은 절 안에서 번갈아 썼다. 짧은 이름을 소개한 적이 없어, 읽는 이가 같은 것인지 더 넓은 범주인지 판단해야 했다. **연구질문 하나가 그 조절변수에 걸려 있었다.**
  이 갈래는 **기계가 못 잡는다.** 낱말 대장도 이음 대조도 통과한다. 실제로 검사를 만들어 봤으나 `safety and`, `et al` 같은 토막까지 올라와 쓸 수 없었다. **전체 층에서 사람이 읽어야 나온다.**
- **그들의 논문을 한 편 통독하고 바로 우리 것을 통독한다.** 붙여 읽으면
  톤 차이가 드러난다

## §6-2. 수치에 붙은 인용 전수 감사 (별도 회차)

층위 훑기와 별개로, **원고에서 수치 옆에 인용이 붙은 자리를 전부 뽑아 한 표로
만들고 원문을 하나씩 연다.** 문턱값·기준선·유의수준·표본 기준·하이퍼파라미터
범위·"관행적으로 쓰이는" 값이 대상이다.

이 감사를 따로 두는 이유는 하나다. **다른 어떤 검사로도 안 잡힌다.** 실제로
검사를 105회 돌리고도 못 잡은 것이 여기서 나왔다.

> 우리는 "the conventional threshold of 5 (O'Brien, 2007)"라고 썼는데, 원문은
> "The practice of automatically questioning the results of studies when the
> variance inflation factor is greater than 4, 10, or even 30 is inappropriate."
> 라고 말한다. **경험칙을 권위로 든 게 아니라 경험칙을 비판하는 논문이었고,**
> 그 논문이 다루는 값은 4·10·30으로 **5는 나오지도 않는다.**

원고 문장은 문법도 맞고 인용 형식도 맞고 검사기도 통과한다. **원문을 열어야만
보인다.**

| 원고 위치 | 수치 | 붙인 인용 | 원문에 그 값이 있나 | 원문이 지지/비판 | 원문의 조건이 같나 | 판정 |
|--|--|--|--|--|--|--|
| 3.5절 | 5 | O'Brien 2007 | 없음(4·10·30) | **비판** | - | 인용 삭제, 우리 근거로 재작성 |

넷 중 하나라도 어긋나면 인용을 빼고 우리 근거로 다시 쓴다. "관행"이라고 쓰고
싶으면 **실제로 그 값을 쓴 게재작**을 찾아 그것을 인용한다. 못 찾으면 관행이라고
쓰지 않는다.


### 참고문헌 제목만 읽어도 잡히는 것이 있다

이 사고는 **참고문헌 목록에서 제목만 읽었어도** 잡혔다. 목록에 이렇게 적혀
있었다.

> O'Brien, R. M. (2007). **A caution regarding rules of thumb for variance
> inflation factors.** Quality & Quantity, 41, 673-690.

제목이 "분산팽창지수 경험칙에 대한 경고"다. **경험칙을 권위로 인용하면서 그
경험칙을 경고하는 논문을 달아 놓은 것이고, 그 사실이 자기 참고문헌 목록에
그대로 적혀 있었다.**

그래서 검수에 값싼 회차를 하나 더 둔다. **참고문헌 목록의 제목을 처음부터
끝까지 소리 내 읽으면서, 그 제목이 본문에서 그 인용을 쓴 방향과 맞는지 본다.**
`caution`, `rethinking`, `myth`, `misuse`, `revisited`, `a note on`, `against`
같은 낱말이 제목에 있으면 그 인용은 반드시 원문을 연다. 10분이면 끝나고, 원문을
다 열지 않아도 방향 오류의 상당수가 여기서 걸린다.

```bash
# 수치 옆에 인용이 붙은 자리를 뽑는 출발점 (판정은 원문을 열어서 한다)
grep -nE "[0-9][^.]{0,80}\((19|20)[0-9]{2}\)|\([A-Z][a-z]+,? (19|20)[0-9]{2}\)[^.]{0,40}[0-9]" 원고.md
```

## §7. 반복 수렴 루프

여기가 이 문서의 마지막이자 실제로 품이 가장 많이 드는 부분이다.

```
(1) 대조·수정을 한 층위 끝낸다
(2) 클로드 관점에서 그 층위를 처음부터 다시 읽는다
    - 기계 결과를 보지 않는다
    - 대장을 보지 않는다 (내가 방금 고쳤다는 사실을 잊고 읽는다)
    - 걸리는 곳만 적는다
(3) 걸린 것이 있으면 §2의 여섯 걸음으로 게재작과 대조해 대체한다
(4) 다시 (2)로
(5) 새로 걸리는 것이 없으면 그 층위를 닫는다
```

### 수렴 조건

- **연속 두 번의 재독에서 새 지적이 0건**이면 그 층위를 닫는다
- 세 번을 돌아도 계속 나오면 **그 자리는 문장 문제가 아니라 내용 문제다.**
  문단 메시지나 절 구성으로 올라가서 본다

### 되돌림 규칙

- 고쳐서 나빠졌으면 **원문으로 되돌리고 그 사실을 대장에 남긴다.** 실제로
  확정했던 수정 하나를 사용자 지적으로 되돌린 적이 있고, 그 기록이 나중에
  같은 자리를 다시 건드리지 않게 막았다
- **같은 자리를 세 번 이상 고치고 있으면 멈춘다.** 판정 기준이 흔들린다는
  신호다. 게재작 문장을 다시 읽고 기준을 먼저 정한다

### 끝을 정한다

무한히 돌 수 있으므로 기준을 미리 못 박는다.

1. 이 지적이 **desk reject 사유인가** → 무조건 고친다
2. 아니면 **게재작 기준으로 할 만한가** → 게재작이 그렇게 하면 고친다
3. 게재작이 안 하는 것이면 **하지 않는다**

"더 매끄러운가"가 아니라 **"게재작 대비 적절한가"**가 기준이다.

## §7-2. 무한루프에 빠지지 않기

수렴 루프는 그냥 두면 끝나지 않는다. **멈추는 조건을 미리 못 박는다.**

| 멈추는 조건 | 기준 |
|--|--|
| **정상 종료** | 연속 두 번의 재독에서 새 지적 0건 |
| **회차 상한** | 한 층위 **최대 5회**. 넘으면 그 층위를 닫고 남은 것을 "미해결"로 적는다 |
| **같은 자리 반복** | 한 자리를 **세 번** 고치면 멈춘다. 판정 기준이 흔들린다는 신호다 |
| **왕복 감지** | A로 고쳤다가 B로 되돌렸다가 다시 A면 **멈추고 저자에게 묻는다** |
| **지적이 안 줄어듦** | 세 회차 연속 지적 수가 안 줄면 문장 문제가 아니라 내용 문제다. 위 층위로 올라간다 |
| **범위 이탈** | 지적이 원고 밖(추가 분석·새 자료)을 요구하면 그 자리에서 끊는다 |

### 반복을 만드는 흔한 원인

1. **기준을 안 적고 고친다.** 다음 회차에 다른 기준으로 다시 고친다
   → 판정을 대장에 적고, **유지도 기록한다**
2. **닫은 층위를 다시 연다** → 닫힌 층위는 그 층위의 문제로 다시 열지 않는다.
   문단을 고쳐 문장이 새로 생긴 경우만 예외
3. **완벽을 목표로 삼는다** → 기준은 "더 나은가"가 아니라 **"게재작 대비
   적절한가"**다
4. **저자 결정이 필요한 것을 우리가 계속 만진다** → "결정 필요"로 빼서
   목록에 올린다

### 멈출 때 남기는 것

```
낱말 층: 5회차에서 닫음. 미해결 3건(저자 결정 대기)
  - 반복 지적: `unassigned` (3회 고침 → 멈춤, 저자 결정으로)
  - 왕복: 없음
```

**"아직 완벽하지 않다"는 이유로 계속 돌지 않는다.** 남은 것을 적고 넘어간다.

## §8. 게재작에서 같은 자리를 찾는 법

### 검색 조리법

```bash
# 결과 문단이 표를 어떻게 지시하는가
python scripts/find_usage.py --journal <저널> --before 1 --after 1 "Table [0-9] (shows|reports|presents)"

# 한계를 어떻게 여는가
python scripts/find_usage.py --journal <저널> "One limitation|limitation of (this|our) study|Nevertheless"

# 절차를 어떤 시제·인칭으로 쓰는가
python scripts/find_usage.py --journal <저널> "we (constructed|computed|assembled|scored|selected)"

# 갭을 어떻게 여는가
python scripts/find_usage.py --journal <저널> "remains (unclear|unexplored|open)|has not been|Harder to find"

# 선택을 어떻게 정당화하는가
python scripts/find_usage.py --journal <저널> "as it is (considered|widely)|following (prior|previous)"

# 결과 강도를 어떤 동사로 쓰는가
python scripts/find_usage.py --journal <저널> "results (indicate|suggest|show|demonstrate)"

# 경계 문장을 어떻게 쓰는가
python scripts/find_usage.py --journal <저널> "do(es)? not (imply|mean|tell)|cannot be (ruled|determined)"

# 우리 낱말이 어떤 뜻으로 쓰이는가
python scripts/find_usage.py --journal <저널> --per-file 3 "<낱말>"
```

**찾은 문장 수를 세어 적는다.** "11편 중 3편만 이렇게 한다"면 그것은 규칙이
아니라 선택지다. 그때는 **저널 때문이 아니라 우리 원고 안의 일관성 때문에**
고친다고 적는다.

### 추출 텍스트를 다룰 때 주의

- PDF 텍스트는 **문장 가운데에 줄바꿈**이 들어간다. 한 줄 검색으로는 문장이
  안 잡힌다(`find_usage.py`가 공백을 정규화해 준다)
- **합자와 분철**이 깨져 있다: `ofﬁces`, `struc­ ture`, `technol- ogy`.
  낱말이 안 찾아지면 "없다"가 아니라 "끊겼다"를 먼저 의심한다
- **인용으로 쓸 문장은 반드시 원문 PDF에서 다시 확인한다.**
  `pdf_render.py`로 그 쪽을 이미지로 보는 것이 가장 확실하다
- 문장이 놓인 자리를 본다. **본문인지, 그림 설명글인지, 각주인지, 저자가 남을
  인용한 대목인지**(`02_통독_기록형식.md` §11)

## §9. 진행 관리

전수 대조는 며칠이 걸린다. **중단해도 이어갈 수 있게** 관리한다.

- 대장 맨 위에 **"지금 어느 층위, 어디까지"**를 적는다
- 층위를 섞지 않는다. 낱말 층을 돌다가 문단이 눈에 걸려도 **적어만 두고**
  계속 낱말을 본다
- 한 층위가 끝나면 **닫았다고 적는다.** 닫힌 층위는 다음 회차에서 다시 열지
  않는다(문단을 고쳐서 문장이 새로 생긴 경우는 예외)
- 하루 분량을 정해 둔다. 지쳐서 판정이 느슨해지는 것이 가장 위험하다

## §10. 하지 말 것

- **기계 결과를 근거로 대지 않는다.** "검사기 통과"는 판정이 아니다
- **코퍼스에 없는 말을 밖에서 가져오지 않는다**
- **선례를 지어내지 않는다.** 못 찾으면 못 찾았다고 적는다
- **한 번에 여러 층위를 보지 않는다**
- **매끄럽게 만든다고 의미를 바꾸지 않는다.** 조건절·범위 한정어를 빼면 주장이
  넓어진다
- **AI가 새 논증·새 인용·새 해석을 만들어 붙이지 않는다.** 톤을 맞추는 것은
  같은 내용을 그 저널의 방식으로 다시 쓰는 일이다
