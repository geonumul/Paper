# AI 티 제거와 최종 파일 위생

> **이 문서의 숫자를 그대로 쓰지 마세요.**
> 절차와 규칙은 분야·저널과 무관하게 쓰지만, 숫자와 사례는 **특허·건설 분야
> 논문 한 편(목표 저널 TFSC)에서 실제로 잰 값**입니다. 〔사례〕 표시가 붙은
> 것은 전부 그 논문 이야기입니다. **자기 저널에서 같은 방식으로 다시 재서
> 바꿔 넣으세요.** 무엇을 재는지가 이 문서의 내용이고, 얼마가 나오는지는
> 저널마다 다릅니다.


**진짜 방어는 문장 규칙이지 도구가 아니다.** 마지막 절(파일 위생)은 십 분이면
끝나고, 앞의 규칙을 어기면 도구로 못 막는다.

---

## §1. 가장 중요한 한 줄

> 사실 오류, 수치 오류, 내적 불일치 교정은 계속한다.
> **새 논증, 새 인용, 새 해석을 AI가 만들어 붙이는 일은 하지 않는다.**
> 게재작 선례에 있는 것만 쓰거나, 없으면 저자에게 맡긴다.

> **실제 사고**: 논의 절에 이론 인용과 우리 주장을 엮어 "그래서 결과가 예측을
> 확인해 준다"는 문단을 새로 만들어 넣었다. 재료(인용, 앞 절 주장)는 다
> 실재했고, 인용도 원문과 대조해 왜곡이 없음을 확인했으며, 다음 문단이 그
> 주장을 실증으로 뒷받침하는 구조까지 갖췄다. **그런데도 연결 자체를 AI가
> 구성한 순간 AI 티가 난다.** 문단 전체를 삭제하고 원래 문장으로 복원했다.

## §2. 문장 규칙 (13부)

**리듬**

- 짧은 문장과 긴 문장을 섞는다. **균일 길이 연속 금지**
- 문장 길이 변동계수를 실측 대역과 대조한다(`check_ngram.py`)

**나열**

- **삼항 나열(A, B, and C) 남발 금지.** 실제로 개수가 정해진 열거에만
- 대구·대칭 문형의 반복 금지(AI가 좋아하는 균형 잡힌 병렬)

**접속**

- **연속 문장을 접속부사로 시작하지 않는다**(Moreover → Furthermore →
  In addition 사슬 금지)

**금지어**

delve, landscape(비유), pivotal, crucial 남발, underscore, foster,
"In today's rapidly evolving", "It is worth noting", "It is important to note",
"plays a vital/crucial/key role", not only … but also 남발, 콜론 나열 남발,
novel 남발, state-of-the-art, unveiling, disruptive.

**배치**

- **구체가 먼저.** 일반론 문장보다 실명·수치·사례가 앞에 오게

**시점 자세**

- 서론 본문은 **연구 시작 전에 쓸 수 있는 문장만**. 결과를 알고 쓴 티는 생성된
  글의 부자연스러움과 비슷하게 읽힌다

## §2-2. 기호·서식 치환표

생성 도구에서 붙여 넣으면 **사람이 잘 안 쓰는 문자**가 딸려 온다. 글자 하나
때문에 티가 나므로 전수로 바꾼다.

| 문자 | 보이는 모양 | 바꿀 것 | 왜 |
|--|--|--|--|
| U+2014 em dash | — | **하이픈, 쉼표, 마침표** | 전역 금지. 생성물에서 가장 흔한 표시 |
| U+2013 en dash | – | 숫자 범위는 **하이픈**(5-10), 그 밖에는 쉼표 | 저널 서식과 어긋나고 눈에 띈다 |
| U+2018 U+2019 곡선 작은따옴표 | ' ' | **곧은 따옴표** `'` (조판은 tex가 한다) | 붙여넣기 흔적 |
| U+201C U+201D 곡선 큰따옴표 | " " | **곧은 따옴표** `"` | 같음 |
| U+2026 줄임표 | … | 인용 생략이면 그대로, 그 밖에는 **마침표 셋** | 인용 생략 표시와 장식용을 갈라 쓴다 |
| U+2022 U+25AA U+2023 불릿 | • ▪ ‣ | 목록은 `-`, 본문이면 **문장으로 풀어 쓴다** | 본문에 불릿이 있으면 발표 자료처럼 읽힌다 |
| 화살표 | → ⇒ ← | 본문에서는 **말로 푼다**("A에서 B로") | 그림·표 안에서만 허용 |
| 이모지 | 아무거나 | **전부 삭제** | 논문에 쓸 일이 없다 |
| U+00A0 줄바꿈 없는 공백 | (안 보임) | 정당한 자리는 유지(`Table 1`, `5 kg`) | 전부 지우면 조판이 깨진다 |
| 폭 없는 공백·제어문자 | (안 보임) | **삭제** | §6 |
| 곱셈 `x` | x | **×** | 서식 규정 |
| `.5` | .5 | **0.5** | 소수점 앞 0 |

**굵게·기울임도 본다.** 초고에 굵게가 많으면 생성물 티가 난다. 게재작 본문에
굵게가 거의 없으면 **표·캡션·수식 기호를 빼고는 쓰지 않는다.** 강조는 문장
순서로 한다.

### 검사와 치환

```bash
python scripts/check_invisible.py 원고.md            # 검사만 (개수와 위치)
python scripts/check_invisible.py 원고.md --fix      # 원고.fixed.md 로 치환
diff 원고.md 원고.fixed.md                            # 반드시 대조
```

**치환은 문자만 바꾼다. 낱말과 문장은 건드리지 않는다.** 바꾼 뒤에는 반드시
`diff`로 대조해서 **글자가 바뀌지 않았는지** 확인한다. 바뀌었으면 되돌린다.

줄바꿈 없는 공백과 줄임표는 **정당하게 쓰이는 자리가 있어서 자동으로 안 바꾼다.**
보고만 하고 눈으로 판단한다.

## §3. 표절·유사도 대비

- **선행연구 문장을 구조째 빌리지 않는다.** 내용은 가져오되 문장 골격(주어
  선택·절 순서·연결 방식)을 우리 것으로 다시 세운다
- **옛 초고의 문장을 재사용하지 않는다.** 사실과 인용만 가져온다
- 정의·공식 표현(계수 식 등)은 예외로 인용과 함께 정확히
- 인용문은 따옴표와 출처로만
- **귀속 인용이거나 완전 재구성이거나 둘 중 하나만.** 어중간한 근접 의역이
  가장 나쁘다

## §3-2. 표절 검사 보고서 읽는 법

투고 전에 유사도 검사를 한 번 돌린다(학교나 기관에서 제공하는 도구). **점수
하나로 판단하지 않는다.** 어디가 겹쳤는지를 보고 종류별로 처리한다.

### 종류별 처리

| 겹친 자리 | 처리 |
|--|--|
| **참고문헌 목록** | 그대로 둔다. 서지는 원래 같다. 보고서에서 제외 설정을 켠다 |
| **방법의 표준 표현**("we used a logistic regression with...") | 그대로 둔다. 표준 문구다 |
| **인용부호 안의 직접 인용** | 그대로 둔다. 출처가 붙어 있으면 문제없다 |
| **우리 옛 원고·학위논문·학회 발표문** | **자기 표절이 될 수 있다.** 재사용 범위를 저널 규정에서 확인하고, 겹치면 다시 쓴다 |
| **선행연구 본문과 겹치는 서술** | 다시 쓴다. **귀속 인용이거나 완전 재구성이거나 둘 중 하나만** |
| 정의·공식 | 인용과 함께 정확히 쓴다 |

### 판단 기준

- **총점보다 "한 출처와 얼마나 겹치는가"**를 본다. 여러 출처에 조금씩 흩어진
  것과 한 논문과 길게 겹치는 것은 전혀 다르다
- 연속으로 겹치는 낱말 수를 본다. 우리 기준은 **5단어 연쇄**다
  (`check_ngram.py`가 미리 잡아 준다)
- 걸린 자리는 **원문을 열어** 우리가 무엇을 가져왔는지 확인한다

### 검사 전에 미리 줄이는 법

`check_ngram.py`로 인용 문헌과의 5-gram 겹침을 먼저 0으로 만들어 두면, 실제
검사에서 남는 것은 대개 참고문헌과 표준 문구뿐이다.

## §4. 두 스캔은 수동 판정한다

| 스캔 | 실측 결과 | 판정 |
|--|--|--|
| 삼항 나열 | 47건 | **결함 0건.** 전부 개수가 정해진 필요한 열거(모델 5개 이름, 코드 목록, 구간 3개) |
| 연속 문장 동일 개시어 | 10건 | **전부 장르 관행.** 로드맵 문단("Section 2… Section 3…"), 단계 서술("Stage 1… Stage 2…"), 연구질문 되받기("In response to RQ1… RQ2…")는 오히려 요구되는 병렬구조 |

**이 두 스캔에서 걸린 것을 그대로 고치면 원고가 나빠진다.**

## §5. 글 밖의 AI 티

- **그림**: 둥근 모서리·파란 채색·산세리프·부드러운 그리드는 "웹앱 대시보드"
  스타일이다. 게재작은 세리프체·각진 모서리·사방 검정 테두리·그리드 없음·절제된

- **국문**: 은유와 도치가 많은 문체는 에세이투다. 변환표는 `06_국문문체.md`

## §6. 최종 파일 위생

여기까지가 글 자체의 작업이었다. 마지막으로 **파일**에 남은 흔적을 치운다.

### 6-1. 무엇이 문제인가

생성 도구에서 텍스트를 붙여넣는 과정에서 **눈에 안 보이는 문자**가 딸려 들어온다
(폭 없는 공백, 특수 공백, 양방향 제어 문자, 태그 문자). 화면에는 안 보이지만
파일에는 남는다. 그리고 워드나 PDF로 내보내면 **문서 속성**에 작성 도구·작성자·
편집 이력이 붙는다. 이중 익명 심사에서는 이것이 익명성 유출이 된다.

### 6-2. 우리 스크립트로 검사

```bash
python scripts/check_invisible.py 원고.md
```

**주의**: 줄바꿈 없는 공백(U+00A0)은 정당하게 쓰이기도 한다("Table 1", "5 kg"에서
줄이 갈라지지 않게 일부러 넣는 경우). 전부 지우지 말고 하나씩 본다.

### 6-3. 외부 도구를 쓸 경우

`https://github.com/guillaumemeyer/watermarks-remover` (파이썬 3.10 이상,
표준 라이브러리만 사용). 세 층 중 **A층과 파일 정리만 쓰고 B층은 쓰지 않는다.**

| 층 | 하는 일 | 권고 |
|--|--|--|
| A층 | 보이지 않는 유니코드 문자 제거 | **쓴다** |
| 파일 정리 | C2PA·EXIF·XMP·문서 속성 제거 | **쓴다** |
| B층 | 통계적 워터마크를 없애려고 본문을 다시 씀 | **쓰지 않는다** |

B층을 쓰면 안 되는 이유는 저장소 README가 스스로 말한다.

> "Stripping a statistical mark requires rewriting a substantial fraction of
> the text, sentence by sentence… Rewording degrades the copy… flattens tone,
> voice, and precision."

**우리가 몇 달에 걸쳐 만든 것이 바로 그 어조와 정확성이다.** 게다가 README는
"어떤 도구도 '이 글이 공식 검사를 통과한다'고 보증하지 못한다"고 명시한다.
돌려서 얻는 것은 없고 잃는 것만 있다.

**우리 경로에서는 B층을 쓸 일 자체가 없다.** 원고 정본은 markdown이고, 조판은
Overleaf에서 tex로 한다(`10_제출_Elsevier.md` §5). 본문을 다시 쓰는 도구가
들어갈 자리가 없다. A층(보이지 않는 문자)과 파일 속성 정리만 하면 되고,
A층은 `check_invisible.py --fix`로도 된다.

절차는 이렇다. **아래 `service/scripts/...`는 그 외부 저장소의 경로다.** 이 스킬에 들어 있는 도구가 아니므로, 쓰려면 그 저장소를 따로 받아야 한다. A층만 필요하면 이 스킬의 `check_invisible.py --fix`로 끝난다.

```bash
# 1. 검사만 (고치지 않는다)
python service/scripts/inspect_text.py 원고.md
#    판정 등급: confirmed(제거) / probable(제거) / informational(눈으로 판단)
#              / likely_false_positive(건드리지 않는다)

# 2. A층만
python service/scripts/clean_text.py 원고.md -o 원고.cleaned.md --stats
#    --stats 숫자를 기록에 남긴다

# 3. 반드시 원본과 대조
diff 원고.md 원고.cleaned.md
#    보이지 않는 문자만 사라졌는지 확인. 글자가 바뀌었으면 되돌린다

# 4. 제출 파일 속성 제거
python service/scripts/clean_file.py 원고.pdf -o 원고.cleaned.pdf
```

**PDF 주의**: exiftool만으로는 원래 메타데이터 바이트가 파일 안에 그대로 남는다.
`qpdf --linearize`로 구조를 다시 만들어야 실제로 지워진다. qpdf를 미리 설치한다.

**그림 파일**: 메타데이터는 확인하되 **픽셀을 건드리는 옵션은 쓰지 않는다.**
우리 그림은 우리가 데이터로 그린 것이라 지울 워터마크가 없고, 픽셀을 건드리면
그림만 나빠진다.

윈도우에서는 `python3` 대신 `python`을 쓴다. **가상환경이 파이썬을 가로채는
경우가 있으니 안 되면 실행 파일 경로를 명시한다.**

### 6-4. 마지막은 눈으로

도구가 다 잡아 주지 않는다. **본문·각주·감사의 말·파일 이름·저장소 주소에
실명이나 소속이 남아 있는지 직접 검색한다.**

## §7. 체크리스트

```
□ 변동계수가 실측 대역 안
□ 삼항 나열·개시어 반복 스캔을 돌리고 전수 수동 판정했다
□ 금지어 0건 (검사기 통과)
□ 5-gram 겹침 0건 또는 귀속 인용
□ AI가 만든 논증·인용·해석이 원고에 없다
□ 그림 스타일을 게재작과 대조했다
□ 보이지 않는 문자 검사 후 A층만 정리, diff로 대조
□ PDF 속성 제거 (qpdf 사용)
□ 익명성 눈으로 확인
□ B층(본문 재작성) 안 돌렸다
```
