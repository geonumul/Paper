# 기록 운영

> **이 문서의 숫자를 그대로 쓰지 마세요.**
> 절차와 규칙은 분야·저널과 무관하게 쓰지만, 숫자와 사례는 **특허·건설 분야
> 논문 한 편(목표 저널 TFSC)에서 실제로 잰 값**입니다. 〔사례〕 표시가 붙은
> 것은 전부 그 논문 이야기입니다. **자기 저널에서 같은 방식으로 다시 재서
> 바꿔 넣으세요.** 무엇을 재는지가 이 문서의 내용이고, 얼마가 나오는지는
> 저널마다 다릅니다.


논문 하나가 끝날 때쯤이면 기록이 원고보다 커진다. **어디에 무엇을 적는지가
정해져 있지 않으면 기록이 많아질수록 답이 틀린다.**

## 1. 파일을 다섯 갈래로 나눈다

| 파일 | 무엇 | 성질 |
|--|--|--|
| **통독 기록** | 논문 한 편당 한 항목 | 길어도 된다. 시점 기록 |
| **문제 일지** | 충돌·미해결 쟁점을 번호 붙인 카드로 | 시점 기록. 옛 카드는 옛 수치를 담고 있다 |
| **정본 파일** | 논문에 실제로 들어갈 것만. 확정된 수치와 문장 | **현재 상태.** 원고와 함께 갱신 |
| **결정 대장** | 장별로 "이 장에서 이미 정한 것" | 집필 착수 전에 조회 |
| **기억 카드** | 다음 대화에서 잊으면 안 되는 것 | 한 카드에 한 사실 |

**섞이면 사고가 난다.** 시점 기록을 정본처럼 읽어서 난 사고가
`12_실패사례집.md` B1이다.

## 2. 문제 일지 카드

```markdown
## N번. 한 줄 제목 (날짜, 상태)

### 어떻게 발견했나
### 무엇이 문제인가
### 답의 재료 (계산한 것, 원문 인용, 선례)
### 무엇을 해야 하나
### 결정 상태: 해결 / 답 확보 / 사용자 결정 대기 / 실행 대기
```

- **결정 상태를 반드시 적는다.** 대기 중인 것은 따로 모아 언제든 목록으로 낼 수
  있게 한다
- 카드는 **짧은 문장으로, 읽자마자 이해되게** 쓴다. 전문 용어는 문서 앞에
  세 낱말쯤 풀어 놓고 시작한다
- **일지 맨 위에 "현행 정본 수치 안내"를 붙인다.** 옛 카드의 수치가 그 시점의
  기록임을 명시하고, 원고에 옮길 때는 정본 값을 쓰라고 적는다

## 3. 결정 대장

장마다 하나씩 만든다. **그 장을 쓰기 전에 확정 구성·일지·기억에서 그 장에 걸린
결정을 전부 뽑아 한 문서로 모은다.**

```markdown
# 결정 대장 - N장

## 1. 이 장에서 이미 정한 것 (근거와 날짜)
## 2. 이 장에서 쓸 수치 (산출 파일 이름과 함께)
## 3. 이 장의 금지 서술 (수위 초과·폐기된 표현)
## 4. 아직 안 정한 것
```

3절이 특히 중요하다. 금지 사항이 여러 문서에 흩어져 있으면 반드시 어긴다.

## 4. 산출물은 스크립트와 결과를 쌍으로 남긴다

```
scripts/census_114_rq3_canonical.py    ← 계산
outputs/census_114_rq3_canonical.md    ← 결과와 해석
```

- 번호를 붙이면 **일지와 원고에서 "census_114"로 지목**할 수 있다
- 원고의 수치 옆, 그림 스크립트의 데이터 옆에 **산출 파일 이름을 주석으로** 단다
- 실행 로그(어떤 파이썬으로, 언제, 어떤 설정으로)를 함께 남긴다

## 5-2. 원고 판본 관리

**판본이 섞이면 수치가 섞인다.** 실제로 v1·v2·중복 제거판이 함께 남아 있어
옛 수치가 원고로 흘러간 적이 있다.

### 규칙

1. **정본은 언제나 하나다.** 파일 첫 줄에 "이 파일이 정본"이라고 적는다
2. **정본은 markdown 하나.** tex·PDF·국문 대역은 전부 정본에서 파생된 것이며,
   **파생본을 직접 고치지 않는다**
3. 판본 이름에 **날짜를 넣는다**: `원고_2026-08-24.md`. `최종`, `진짜최종`,
   `수정본2`를 쓰지 않는다
4. 옛 판본은 `archive/`로 옮기고 **파일 첫 줄에 "폐기, 사유"를 적는다.**
   지우지는 않되 검색에 걸려도 헷갈리지 않게 한다
5. **수치가 바뀌면 옛 수치를 검사기 금지 목록에 즉시 등록한다**
   (`14_할루시네이션_방지.md` §4)

### 판본을 새로 뜰 때

- 무엇이 바뀌었는지 한 줄로 적는다(변경 기록)
- **파생 파일을 전부 다시 만든다**: tex·PDF·그림·국문 대역·서약 문서
- 정본 폴더(`14` §3)를 같이 고친다
- 저장소 스크립트가 새 그림을 만드는지 실제로 돌려 본다

### 파일 이름

| 무엇 | 이름 | 비고 |
|--|--|--|
| 원고 정본 | `원고_YYYY-MM-DD.md` | 영문이 정본이면 국문은 `_국문` |
| 조판본 | `manuscript.tex` / `.pdf` | 정본에서 생성. 손으로 안 고침 |
| 그림 | `figN_이름.pdf` / `.png` | **번호 = label = 인쇄 번호** |
| 산출 | `census_NNN_이름.md` / `.py` | 결과와 스크립트를 쌍으로 |
| 폐기 | `archive/...` | 첫 줄에 폐기 사유 |

## 6. 검수 계획 문서

회전을 돌기 전에 계획을 표로 만들고, 회전이 끝날 때마다 **완료 기록을 같은
문서에 덧붙인다.**

```markdown
|회전|범위|내용|상태|
|--|--|--|--|
|0-A|스타일 규범화|게재작 관찰 → 규칙서, 리듬 대역 실측|완료|
|0-B|기계 전수|금지어·5-gram·리듬·정합|도구 완료, 탈고 후 일괄|
|1-2|1장|문단별 수동 9층 + 원문 대조|진행 중|
...
## 회전 1 완료 기록 (날짜)
- 무엇을 검사했고, 무엇을 고쳤고, 무엇을 안 고쳤는지
```

**안 고친 것과 그 이유를 적는 칸이 있어야 한다.** 없으면 같은 지적이 회전마다
다시 올라온다.

## 7. 재개 문서

작업을 중단할 때 `RESUME_다음에_할것.md` 하나를 갱신한다.

- 지금 어디까지 했는가
- 다음에 무엇부터 하는가
- 실행했으나 결과를 아직 확인 못 한 것이 있는가
- 사용자 결정을 기다리는 것이 무엇인가

**"실행했으나 결과 미확인"을 적어 두지 않으면 다음에 다시 돌린다.**

## 8. 기억 카드 규칙

- **한 카드에 한 사실**
- 앞에 `name`·`description`·`type`을 두고, 본문에 왜 그런지와 어떻게 적용하는지를
  적는다
- **날짜를 박는다.** 상대 날짜를 쓰지 않는다
- 낡으면 **제목·요약·본문 전부에** 폐기 표시를 넣는다
- 인덱스 파일에는 **한 줄씩만.** 내용을 인덱스에 적지 않는다
- **저장소에는 올리지 않는다**
