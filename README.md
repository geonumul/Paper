# paper-to-journal

**목표 저널에 실린 논문을 자로 삼아, 논문을 쓰고 검수하고 투고 파일까지 만드는
Claude Code 스킬입니다.**

"이게 더 자연스럽다"로 고치지 않습니다. 고치는 근거는 언제나 **그 저널에 실제로
실린 논문이 그렇게 쓴다**입니다. 그래서 이 스킬은 글을 고치는 일이 아니라
**재는 일**에서 시작합니다.

논문 한 편을 이 방식으로 마무리하면서 실제로 거친 과정과, 그 과정에서 낸 사고를
그대로 옮겨 놓았습니다.

---

## 무엇을 하나

```
0  묻기        주제 / 목표 저널(안 정했으면 추천) / 가진 논문
1  모으기      게재작을 찾아 제목 목록을 만들어 드림 → 받아서 폴더에
2  재기        문장 길이·리듬·이음말 밀도·한계 분량·참고문헌 수를 숫자로
3  통독        한 편씩 직렬로 읽고 같은 칸을 채움 (배치 병렬 금지)
4  구조        게재작 목차를 나란히 놓고 우리 목차를 정함 (저자가 고름)
5  뼈대        문단마다 메시지 한 줄과 문장이 하는 일을 표로 쌓아 승인받음
6  집필        승인된 뼈대대로 씀
7  기계 검사   문체·리듬·5-gram·규격·참조·수치 정합
8  직접 대조   낱말 → 문장 → 문단 → 소절 → 장 → 전체를 전수로, 게재작 근거를 대고
9  그림·표     게재작 양식을 수치로 재고 이미지로 보고 베낌
10 투고        LaTeX·CRediT·서약·익명·파일 위생
```

**8번이 본체입니다.** "이건 어떤 근거로 이렇게 썼어?"에 "게재작 X의 어느 자리가
이렇게 하고, 우리 자리도 같은 기능이라 그 방식을 따랐다"고 답할 수 있어야
검수가 끝납니다.

---

## 네 가지 원칙

1. **기준은 감이 아니라 게재작 실측이다.** 재지 않았으면 "재지 않았다"고 말한다
2. **AI가 새 논증·새 인용·새 해석을 만들어 붙이지 않는다.** 사실·수치·불일치
   교정은 계속하되, 연결을 AI가 구성하면 티가 난다
3. **기계는 후보만 내고 판정은 사람이 한다.** 기계가 만든 목록은 "여기까지 봐야
   한다"는 뜻이지 "봤다"는 뜻이 아니다
4. **연구의 뼈대는 저자가 정한다.** 스킬은 근거를 붙인 선택지를 만들어 드리고,
   고른 것을 기록하고, 나머지를 거기에 맞춘다

## 설치

Claude Code가 있어야 합니다.

```bash
git clone https://github.com/geonumul/Paper.git ~/.claude/skills/paper-to-journal
```

윈도우(PowerShell)면 이렇게 합니다.

```powershell
git clone https://github.com/geonumul/Paper.git "$env:USERPROFILE\.claude\skills\paper-to-journal"
```

폴더 이름이 `paper-to-journal`이어야 하고, 그 안에 `SKILL.md`가 바로 보여야
합니다.

**도구를 쓰려면**: Python 3.9 이상. PDF를 다루는 도구는 PyMuPDF가 필요합니다.

```bash
pip install pymupdf
```

## 처음 쓰는 법

Claude Code에서 그냥 이렇게 말하면 됩니다.

> 논문 쓰려고 하는데 도와줘

그러면 스킬이 세 가지를 묻습니다. **주제**가 뭔지, **어디에 낼 건지**(안 정했으면
추천해 드립니다), **모아 둔 논문이 있는지**.

그다음은 이 순서입니다.

**1. 논문을 받습니다.** 검색어를 드리는 게 아니라 직접 찾아서 제목·저자·연도·
링크를 표로 드립니다. 받아서 `literature/5_저널게재작/`에 넣으시면 됩니다.
목표 저널 게재작 최소 20편, 되도록 40편.

**2. 자를 만듭니다.**

```bash
python ~/.claude/skills/paper-to-journal/scripts/check_ngram.py --extract
python ~/.claude/skills/paper-to-journal/scripts/check_ngram.py --calibrate --journal <저널표식>
```

문장 길이와 리듬 대역이 나옵니다. **이 숫자가 없으면 그 뒤가 전부 감으로 하는
일이 됩니다.**

**3. 통독합니다.** 한 편씩, 처음부터 끝까지, 직접. 편마다 같은 칸을 채웁니다.

**4. 그다음부터는 스킬이 안내합니다.** 한 단계가 끝날 때마다 ①한 것 ②정할 것
③다음을 보고합니다. 정할 것은 저자가 고릅니다.

## 읽을 때 주의

**참고문서의 숫자를 그대로 쓰지 마세요.**

절차와 규칙은 분야·저널과 무관하게 썼지만, **숫자와 사례는 특허·건설 분야 논문
한 편(목표 저널 TFSC)에서 실제로 잰 값**입니다. 〔사례〕 표시가 붙은 것은 전부
그 논문 이야기입니다.

- **가져갈 것**: 무엇을 재는가, 어떻게 재는가, 왜 재는가
- **버릴 것**: 얼마가 나왔는가 (저널마다 다릅니다)

실패 사례집도 마찬가지입니다. 이야기는 특허 자료 이야기지만, **각 사례 끝의
`→ 규칙:` 줄은 분야와 무관**합니다.

프로젝트 전용 값(폐기된 옛 수치, 그 논문에서만 금지인 표현, 도구 이름)은
`scripts/style_config.example.json`을 복사해 프로젝트 폴더에 `style_config.json`으로
두면 검사기가 읽습니다.

## 이 스킬이 나온 자리

논문 한 편을 쓰면서 남긴 기록에서 나왔습니다. 문헌 152편 통독, 기록 25,806줄,
문제 일지 카드 70여 개, 검수 회전 10회차. 규칙마다 그것이 나온 사고가 있습니다.

가장 크게 배운 것 하나만 적으면 이것입니다.

> **놓친 것은 전부 직접 읽지 않은 자리에서 나왔다.**
> 논문을 배치로 나눠 읽히자 없는 인용문이 만들어졌고, 검사를 105회 돌리고도
> 원문을 안 열어 인용 오류를 놓쳤고, 의심 가는 낱말만 골라 보다가 저널에 없는
> 말을 놓쳤고, 검수를 열 회차 돌고도 그림 안 글자를 안 봐서 오류를 놓쳤다.
> 반대로 **직접 읽은 자리에서는 전부 나왔다.**
