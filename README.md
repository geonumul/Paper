# paper-to-journal

내려는 학술지에 **이미 실린 논문을 기준으로 삼아** 논문을 쓰고, 검사하고,
투고 파일까지 만드는 Claude Code 스킬이다.

문장을 고치는 근거를 "이게 더 자연스럽다"는 판단에 두지 않는다. 근거는 언제나
**그 학술지에 실린 논문이 실제로 그렇게 쓴다**는 사실이다. 따라서 이 스킬은
글을 고치는 작업이 아니라 **재는 작업**에서 시작한다.

논문 한 편을 이 방식으로 끝내면서 실제로 거친 절차와 그 과정에서 낸 오류를
그대로 옮긴 것이다.

---

## 이 문서에서 쓰는 말

| 말 | 뜻 |
|--|--|
| **게재작** | 목표 학술지에 이미 실린 논문 |
| **실측** | 짐작하지 않고 직접 세어 숫자로 재는 것 |
| **대역** | 게재작을 재서 나온 정상 범위(예: 문장 평균 16-23낱말) |
| **코퍼스** | 게재작 PDF에서 뽑아 모아 둔 텍스트 |
| **통독** | 논문을 처음부터 끝까지 한 편씩 읽는 것 |
| **전수** | 표본을 뽑지 않고 하나도 빠뜨림 없이 전부 |
| **대장** | 검사 대상을 한 줄씩 적고 판정을 채워 넣는 표 |
| **정본** | 기준이 되는 원본 파일. 나머지는 여기서 만들어진 사본 |
| **문단 뼈대** | 문단마다 무슨 말을 할지, 문장마다 무슨 역할을 할지 미리 짜 둔 표 |

## 절차

```
0  확인      주제, 목표 학술지(못 정했으면 후보를 찾아 제안), 가진 논문
1  수집      가진 논문을 먼저 세고, 모자란 만큼만 목록으로 제안한다.
             이미 있는 논문은 그대로 쓰고 다시 받지 않는다
2  실측      게재작을 재서 정상 범위를 만든다
             (문장 길이, 문장 길이가 들쭉날쭉한 정도, 연결어 빈도,
              한계 절 분량, 참고문헌 개수)
3  통독      한 편씩 처음부터 끝까지 읽고 같은 항목을 기록한다
             (여러 편을 나눠서 동시에 읽히지 않는다)
4  구조      게재작의 목차를 나란히 놓고 우리 목차를 정한다 (저자가 고른다)
5  뼈대      문단마다 할 말과 문장마다 할 일을 표로 짜서 승인받는다
6  집필      승인된 뼈대대로 쓴다
7  기계 검사  금지 표현, 문장 리듬, 규격, 표·그림 참조, 숫자 일치 등을 자동 검사
8  대조 검수  낱말·문장·문단·소절·장·전체를 전수로 게재작과 대조한다
9  그림·표    게재작의 그림 양식을 수치로 재고 눈으로 확인해 똑같이 맞춘다
10 투고      조판(LaTeX), 저자 기여 표기, 서약문, 익명 처리, 파일 정리
```

**8단계가 본체다.** "이 문장을 왜 이렇게 썼는가"라는 물음에 "게재작 X의 같은
자리가 이렇게 하고 있고, 우리 자리도 같은 역할이라 그 방식을 따랐다"고 답할
수 있어야 검수가 끝난다.

---

## 원칙

1. **기준은 게재작을 잰 결과다.** 재지 않았으면 "재지 않았다"고 적는다
2. **없던 논증·인용·해석을 생성형 도구가 만들어 붙이지 않는다.** 사실 오류,
   숫자 오류, 앞뒤가 안 맞는 곳을 고치는 데까지만 쓴다
3. **기계는 후보만 내고 판정은 사람이 한다.** 기계가 만든 목록은 "여기까지
   봐야 한다"는 뜻이지 "봤다"는 뜻이 아니다
4. **연구의 뼈대는 저자가 정한다.** 스킬은 근거를 붙인 선택지를 만들어 주고,
   고른 것을 기록하고, 나머지를 그 결정에 맞춘다

## 사용

Claude Code에서 명령으로 부른다.

```
/paper-to-journal
```

부르면 세 가지를 묻는다. 주제가 무엇인지, 어디에 낼 것인지(못 정했으면 자료와
주제를 보고 후보를 찾아 제안한다), 모아 둔 논문이 있는지. **이미 가진 논문이
있으면 그것을 쓰고 모자란 만큼만 더 받는다.**

### 중간부터 시작하기

작업이 이미 진행되었으면 시작 지점을 지정한다. 그 앞 단계는 건너뛴다.

| 명령 | 하는 일 | 있어야 하는 것 |
|--|--|--|
| `/paper-to-journal` | 처음부터 전부 | 없음 |
| `/paper-to-journal 수집` | 논문 모으기와 정상 범위 재기 | 주제, 목표 학술지 |
| `/paper-to-journal 통독` | 논문 읽고 기록하기 | 게재작 PDF |
| `/paper-to-journal 구조` | 게재작 목차를 뜯어보고 우리 목차 정하기 | 통독 기록 |
| `/paper-to-journal 집필` | 문단 뼈대 짜고 쓰기 | 목차 |
| `/paper-to-journal 검수` | **써 둔 원고 검사만** | 원고, 게재작 |
| `/paper-to-journal 번역` | **번역해 둔 두 판이 같은 말을 하는지 검사만** | 두 판 원고 |
| `/paper-to-journal 인용` | **인용이 실제로 맞는지 검사만** | 원고, 인용한 원문 PDF |
| `/paper-to-journal 그림` | 그림·표 양식 맞추기 | 게재작 PDF, 우리 그림 |
| `/paper-to-journal 국문` | 국문 원고 문체 검사 | 국문 원고, 기준이 될 국문 논문 |
| `/paper-to-journal 제출` | 투고 파일 만들기 | 원고, 그림, 투고 규정 |

앞 단계의 결과물이 없으면 **그 사실과, 그래서 무엇을 못 하는지를 먼저
알린다.** 건너뛴 단계는 기록에 남긴다.

### 원고를 이미 쓴 경우

`/paper-to-journal 검수`로 시작한다.

1. 가진 것을 센다(원고, 게재작 몇 편, 뽑아 둔 텍스트가 있는지)
2. **게재작이 없으면 그것부터 받는다.** 정상 범위가 없으면 검사의 근거가
   없다. 최소 20편이 필요하다. 급하면 기준으로 삼을 논문 2-4편만으로
   시작하되, 그렇게 했다는 사실을 기록한다
3. 기계 검사를 먼저 돌린다. 여기서 나오는 것이 가장 싸게 고쳐진다
4. 검사 대상을 전부 뽑아 개수를 보고한다(예: 낱말 2,186개, 문단 203개,
   문장 779개)
5. **어디까지 볼지 저자가 고른다.** 전부 볼지, 층위를 골라서 볼지, 급한
   것부터 볼지
6. 고른 범위는 **끝까지 전부** 본다. 범위를 좁히는 것은 되지만, 좁힌 범위
   안에서 몇 개만 골라 보는 것은 안 된다

### 번역해 둔 원고를 검사하는 경우

`/paper-to-journal 번역`으로 시작한다. 먼저 **어느 쪽이 기준인지** 정하고,
기준이 아닌 쪽을 고쳐서 맞춘다. 도구가 두 판의 문단 수, 숫자, 인용, 약어를
대조해 어긋난 자리를 뽑아 주고, 문단을 짝지어 다섯 가지를 사람이 본다.
같은 말을 하는가, 숫자가 같은가, 주장의 세기가 같은가, 조건을 붙인 말이
빠지지 않았는가, 같은 용어를 같은 말로 옮겼는가.

### 인용만 검사하는 경우

`/paper-to-journal 인용`으로 시작한다. 인용 오류는 문법 검사에도, 문체
검사에도, 표절 검사에도 안 걸린다. **원문을 열어야만 보인다.** 인용을 전부
뽑아 개수를 보고하고, 참고문헌 목록과 양쪽으로 맞춰 보고, 원문을 열어 다섯
가지를 확인한다. 그 논문이 정말 그 말을 하는가, 지지인가 비판인가, 그 숫자가
원문에 있는가, 조건이 같은가, 인용문의 글자가 맞는가.

### 정상 범위를 재는 명령

```bash
python ~/.claude/skills/paper-to-journal/scripts/check_ngram.py --extract
python ~/.claude/skills/paper-to-journal/scripts/check_ngram.py --calibrate --journal <학술지표시>
```

첫 줄은 게재작 PDF에서 글자를 뽑아 모아 두는 것이고, 둘째 줄은 그 글로 문장
길이와 리듬의 정상 범위를 계산하는 것이다. **이 숫자가 없으면 그다음 판단에
근거가 없다.**

각 단계가 끝나면 ①한 것(숫자로) ②정해야 할 것(선택지와 근거) ③다음에 할
것을 보고한다. ②는 저자가 고른다.

## 쓸 때 주의할 것

**참고문서에 적힌 숫자를 그대로 가져다 쓰지 않는다.**

절차와 규칙은 분야와 학술지에 관계없이 쓰도록 썼다. 그러나 숫자와 사례는
특허·건설 분야 논문 한 편에서 잰 값이다. 〔사례〕 표시가 붙은 것은 전부 그
논문 이야기다.

- **가져갈 것**: 무엇을 재는지, 어떻게 재는지, 왜 재는지
- **버릴 것**: 얼마가 나왔는지 (학술지마다 다르다)

실패 사례집도 마찬가지다. 이야기는 특허 자료를 다루지만, 각 사례 끝의
`→ 규칙:` 줄은 분야와 관계없다.

내 논문에서만 쓰는 값(더 이상 쓰지 않는 옛 숫자, 이 원고에서만 금지인 표현,
쓰는 도구 이름)은 `scripts/style_config.example.json`을 복사해 작업 폴더에
`style_config.json`이라는 이름으로 두면 검사기가 읽는다.

## 어디서 나왔나

논문 한 편을 쓰며 남긴 기록에서 나왔다. 논문 152편 통독, 기록 25,806줄, 문제
기록 70여 건, 검수 열 번. 규칙마다 그것이 나오게 된 오류가 하나씩 있다.

그중 가장 중요한 것 하나만 적으면 이렇다.

> **놓친 것은 전부 직접 읽지 않은 자리에서 나왔다.**
> 논문을 여러 개로 나눠 동시에 읽히자 있지도 않은 인용문이 만들어졌고,
> 검사를 105번 돌리고도 원문을 안 열어 인용 오류가 남았고, 의심 가는 낱말만
> 골라 보다가 그 학술지에서 쓰지 않는 말을 놓쳤고, 검수를 열 번 돌고도 그림
> 안의 글자를 안 봐서 오류가 남았다. 반대로 **직접 읽은 자리에서는 전부
> 나왔다.**
