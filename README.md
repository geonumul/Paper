# paper-to-journal

**이미 쓴 논문 원고를, 내려는 학술지에 실린 논문과 대조해 검사하는 Claude Code
스킬이다.**

원고를 대신 써 주지 않는다. **고칠 곳을 근거와 함께 찾아 주는 것**이 전부이고,
고치는 것은 저자가 한다.

지적의 근거를 "이게 더 자연스럽다"는 판단에 두지 않는다. 근거는 언제나 **그
학술지에 실린 논문이 실제로 그렇게 쓴다**는 사실이다.

---

## 이 문서에서 쓰는 말

| 말 | 뜻 |
|--|--|
| **게재작** | 목표 학술지에 이미 실린 논문 |
| **실측** | 짐작하지 않고 직접 세어 숫자로 재는 것 |
| **대역** | 게재작을 재서 나온 정상 범위(예: 문장 평균 16-23낱말) |
| **코퍼스** | 게재작 PDF에서 뽑아 모아 둔 텍스트 |
| **통독** | 논문을 처음부터 끝까지 한 편씩 읽는 것 |
| **전수** | 표본을 뽑지 않고 하나도 빠뜨림 없이 전부 |
| **대장** | 검사 대상을 한 줄씩 적고 판정을 채워 넣는 표 |

## 검사 절차

```
0  확인      검수할 원고, 가지고 있는 논문 폴더, 목표 학술지
1  저널      SCI·SCIE인지 확인하고, 제외 대상을 거른 뒤 하나로 정한다
2  수집      가진 것을 먼저 세고, 모자란 만큼만 목록으로 제안한다
3  실측      게재작을 재서 정상 범위를 만든다
4  인용 분포  그 학술지 논문들이 어느 학술지를 몇 %씩 인용하는지 센다
5  기준      게재작을 한 편씩 읽어 검사 기준을 만든다
6  기계 검사  금지 표현, 문장 리듬, 규격, 표·그림 참조, 숫자 일치
7  전수 대조  낱말·문장·문단·소절·장·전체를 하나씩 게재작과 맞춰 본다
7-2 각도별 읽기 흐름·맥락·방법·결과·문법·내용·독자 관점으로 읽는다
8  인용 검증  원문을 열어 인용이 실제로 맞는지 확인한다
9  번역 대조  번역해 둔 두 판이 같은 말을 하는지 맞춰 본다
10 그림·표    게재작 양식을 수치로 재고 눈으로 확인해 비교한다
11 AI 티     문장 리듬, 티 나는 기호, 안 보이는 문자, 익명 처리
12 투고 점검  분량 규격, 조판, 서약문, 파일 목록
```

**7단계가 본체다.** "이 문장을 왜 이렇게 썼는가"라는 물음에 "게재작 X의 같은
자리가 이렇게 하고 있고, 우리 자리도 같은 역할이라 그 방식을 따랐다"고 답할
수 있어야 검사가 끝난다.

## 어떤 논문을 모으는가

검사 기준은 전부 게재작에서 나오므로, **무엇을 모으느냐가 검사의 질을 정한다.**

### 저널을 고르는 기준

| 조건 | 내용 |
|--|--|
| **SCI·SCIE 등재** | Web of Science 핵심 목록에 올라 있는 학술지만 |
| **분야 적합** | 최근 3년 목차에 우리 대상·방법이 실제로 실렸는가 |

### 기본적으로 빼는 것

| 빼는 것 | 왜 |
|--|--|
| 오픈액세스 전용 학술지 | 게재료 기반 운영이라 평가에서 달리 취급되는 경우가 있다 |
| 대형 오픈액세스 학술지 | 게재량이 크고 분야가 넓어 문체 기준으로 삼기 어렵다 |
| MDPI·Frontiers 계열 | 심사 속도, 특별호 운영, 수용률을 두고 논란이 있어 왔다 |
| 약탈적 의심 학술지 | 기관 지침에서 문제로 지목된 곳 |
| 학회 논문집·워킹페이퍼 | 심사 절차가 다르다. 참고는 하되 문체 기준에는 안 넣는다 |

학술적 우열 판단이 아니라 투고 전략상의 선택이다. **제외했다는 사실과 이유를
기록에 남긴다.**

### 이미 가진 폴더를 먼저 진단한다

세는 것으로 끝내지 않는다. 편수, **텍스트가 안 뽑힌 파일과 스캔본**, 연도
분포, 중복, **원고가 인용했는데 원문이 없는 논문**을 함께 낸다.

```bash
python scripts/lit_audit.py --lit literature --txt literature/_txt --journal <학술지표시> --manuscript 원고.md
```

〔예시〕 전체 156편, 목표 학술지 게재작 42편으로 보였으나 텍스트가 안 뽑힌
것이 39편, 글자가 나오지 않는 스캔본이 4편이었다. 실측에 쓸 수 있는 것은
113편이다.

### 두 갈래로 모은다. 섞지 않는다

목적이 다르므로 표본을 나눈다.

| | 문체·양식 기준용 | 인용용 |
|--|--|--|
| 몇 편 | **최소 40편, 60편 권장** | 원고가 필요로 하는 만큼 |
| 읽는가 | 읽지 않는다. 기계가 잰다 | **전부 읽는다** |
| 고르는 법 | 목표 학술지에 최근 실린 것을 되도록 다 | 우리 문장이 하는 말을 실제로 하는 것만 |

**몇 편이면 충분한지는 재서 정한다.** 편수를 늘려 가며 대역이 얼마나
흔들리는지 본다. 더 안 넓어지면 그만 모아도 된다.

```bash
python scripts/check_ngram.py --calibrate --txt literature/_txt --journal <학술지표시> --stability
```

### 그 학술지가 무엇을 인용하는지 센다

게재작들의 참고문헌에서 학술지 이름을 뽑아 분포를 낸다.

```bash
python scripts/cite_sources.py --txt literature/_txt --journal <학술지표시> --top 25
```

〔예시 출력〕

| 순위 | 인용된 학술지 | 비율 | 몇 편이 인용하나 |
|--|--|--|--|
| 1 | Technological Forecasting and Social Change | 24.5% | 35/35편 |
| 2 | Scientometrics | 6.9% | 32/35편 |
| 3 | Research Policy | 6.8% | 23/35편 |
| 4 | Technovation | 2.4% | 25/35편 |

여기서 셋을 읽는다.

- **자기 학술지를 몇 % 인용하는가.** 우리 원고가 이보다 훨씬 적으면, 그
  학술지 독자가 아는 논문을 안 읽은 것이다
- **상위에 있는데 우리가 안 읽은 학술지.** 그 목록이 곧 추가로 모을 대상이다
- **우리 인용 분포와의 차이.** `--ours 원고.md`를 붙이면 우리 참고문헌
  분포를 나란히 놓고 **더 모아야 할 학술지**를 낸다

```bash
python scripts/cite_sources.py --txt literature/_txt --journal <학술지표시> --ours 원고.md
```

**비율을 맞추려고 인용하지 않는다.** 이 분포는 *모아 올 목록*을 정하는 데까지만
쓴다. 모아 온 뒤에는 한 편씩 읽고, 우리 문장이 하는 말을 그 논문이 실제로
하는지 확인한 것만 인용한다. 맥락이 맞지 않으면 인용하지 않고 그 자리는
모자란 채로 둔다. 모자란 자리가 여럿이면 **비율을 채우는 대신 맞는 논문을 더
찾는다.**

## 원칙

1. **기준은 게재작을 잰 결과다.** 재지 않았으면 "재지 않았다"고 적는다
2. **원고를 대신 쓰지 않는다.** 없던 논증·인용·해석을 만들어 붙이지 않는다.
   대체 표현 후보는 게재작에 실제로 쓰인 말 중에서만 제시한다
3. **기계는 후보만 내고 판정은 사람이 한다.** 기계가 만든 목록은 "여기까지
   봐야 한다"는 뜻이지 "봤다"는 뜻이 아니다
4. **고칠지 말지는 저자가 정한다.** 스킬은 근거를 붙인 선택지를 만들어 주고,
   결정을 기록한다

## 사용

```
/paper-to-journal
```

부르면 세 가지를 묻는다. **검수할 원고**가 어느 파일인지, **가지고 있는 논문
폴더**가 어디인지, **목표 학술지**가 어디인지. 이미 가진 논문이 있으면 그것을
쓰고 모자란 만큼만 더 받는다.

### 무엇만 검사할지 정하기

| 명령 | 하는 일 | 있어야 하는 것 |
|--|--|--|
| `/paper-to-journal` | 전체 검수 | 원고, 게재작 |
| `/paper-to-journal 수집` | 학술지 정하기와 논문 모으기, 정상 범위 재기 | 주제 |
| `/paper-to-journal 기준` | 게재작을 읽어 검사 기준 만들기 | 게재작 PDF |
| `/paper-to-journal 검수` | 낱말·문장·문단·소절·장·전체 전수 대조 | 원고, 게재작 |
| `/paper-to-journal 인용` | 인용이 실제로 맞는지만 | 원고, 인용한 원문 PDF |
| `/paper-to-journal 번역` | 두 판이 같은 말을 하는지만 | 두 판 원고 |
| `/paper-to-journal 그림` | 그림·표 양식만 | 게재작 PDF, 우리 그림 |
| `/paper-to-journal 국문` | 국문 원고 문체만 | 국문 원고, 기준 국문 논문 |
| `/paper-to-journal 구조` | 목차·절 구성이 게재작과 맞는지만 | 원고, 게재작 |
| `/paper-to-journal 제출` | 투고 규격과 파일 점검만 | 원고, 그림, 투고 규정 |

앞 단계의 결과물이 없으면 **그 사실과 그래서 무엇을 못 하는지를 먼저 알린다.**
건너뛴 단계는 기록에 남긴다.

### 검수 진행 방식

1. 가진 것을 센다(원고, 게재작 몇 편, 뽑아 둔 텍스트가 있는지)
2. 게재작이 없으면 그것부터 받는다. **정상 범위가 없으면 검사의 근거가 없다**
3. 기계 검사를 먼저 돌린다
4. 검사 대상을 전부 뽑아 개수를 보고한다(예: 낱말 2,186개, 문단 203개,
   문장 779개)
5. **어디까지 볼지 저자가 고른다.** 전부 볼지, 층위를 골라 볼지, 급한 것부터
6. 고른 범위는 **끝까지 전부** 본다. 범위를 좁히는 것은 되지만, 좁힌 범위
   안에서 몇 개만 골라 보는 것은 안 된다

각 단계가 끝나면 ①한 것(숫자로) ②정해야 할 것(선택지와 근거) ③다음에 할 것을
보고한다. 그리고 **답변마다 진행률 한 줄**이 붙는다.

```
[진행 7/12단계 · 낱말 층 1,204/2,186 (55%) · 남음 982]
```

검수 루프가 끝없이 돌지 않도록 멈추는 조건도 정해져 있다. 연속 두 번 새 지적이
없으면 닫고, 한 층위는 최대 다섯 번까지만 돌고, 같은 자리를 세 번 고치면
멈춘다. 남은 것은 "미해결"로 적고 넘어간다.

## 쓸 때 주의할 것

**참고문서에 적힌 숫자를 그대로 가져다 쓰지 않는다.**

절차와 규칙은 분야와 학술지에 관계없이 쓰도록 썼다. 그러나 숫자와 사례는
특허·건설 분야 논문 한 편에서 잰 값이다. 〔사례〕 표시가 붙은 것은 전부 그
논문 이야기다.

- **가져갈 것**: 무엇을 재는지, 어떻게 재는지, 왜 재는지
- **버릴 것**: 얼마가 나왔는지 (학술지마다 다르다)

실패 사례집도 마찬가지다. 이야기는 특허 자료를 다루지만, 각 사례 끝의
`→ 규칙:` 줄은 분야와 관계없다.

내 논문에서만 쓰는 값(더 이상 쓰지 않는 옛 숫자, 이 원고에서만 금지인 표현,
쓰는 도구 이름)은 `scripts/style_config.example.json`을 복사해 작업 폴더에
`style_config.json`이라는 이름으로 두면 검사기가 읽는다.

## 어디서 나왔나

논문 한 편을 검수하며 남긴 기록에서 나왔다. 논문 152편 통독, 기록 25,806줄,
문제 기록 70여 건, 검수 열 번. 규칙마다 그것이 나오게 된 오류가 하나씩 있다.

그중 가장 중요한 것 하나만 적으면 이렇다.

> **놓친 것은 전부 직접 읽지 않은 자리에서 나왔다.**
> 논문을 여러 개로 나눠 동시에 읽히자 있지도 않은 인용문이 만들어졌고,
> 검사를 105번 돌리고도 원문을 안 열어 인용 오류가 남았고, 의심 가는 낱말만
> 골라 보다가 그 학술지에서 쓰지 않는 말을 놓쳤고, 검수를 열 번 돌고도 그림
> 안의 글자를 안 봐서 오류가 남았다. 반대로 **직접 읽은 자리에서는 전부
> 나왔다.**
